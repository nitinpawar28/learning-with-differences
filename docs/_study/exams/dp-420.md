## What the exam really tests

DP-420 tests whether you can **build applications on Azure Cosmos DB for NoSQL as a production operational store, including as the memory and retrieval layer for AI agents**. The 2026 version drops the old server-side JavaScript, data movement and DevOps areas. It adds AI retrieval, agent memory stores, Fabric analytics, Fleet management and AI-assisted development with Agent Kit.

Themes and depth:

- **Resource model and SDK.** You choose a consistency level (strong, bounded staleness, session, consistent prefix, eventual) and work out the Request Unit cost of reads, writes and queries. You choose a throughput model (provisioned manual, autoscale or serverless; database-level or container-level) and set up a singleton client with the right connection mode and preferred regions.
- **Operations.** Point reads compared with queries, parameterised queries, paging with continuation tokens, patch operations, bulk execution, transactional batch within one logical partition, TTL, and optimistic concurrency with ETags.
- **Data modelling and partitioning, the heart of the exam.** Embedding compared with referencing, partition keys chosen for cardinality and even writes, hierarchical partition keys for multi-tenant designs, synthetic keys, spotting hot partitions and cross-partition fan-out in a design review, and estimating cost.
- **Change feed.** Processor compared with pull model, lease containers, latest version compared with all versions and deletes mode, and copy container jobs.
- **Security, availability and performance.** Microsoft Entra ID with data-plane RBAC compared with keys, network security (private endpoints, firewalls), dynamic data masking, continuous compared with periodic backup and point-in-time restore, multi-region writes and conflict handling, partition-level failover, query and index metrics, Azure Monitor alerts and diagnostic logs in Log Analytics (KQL).
- **Fleet.** Throughput pooling and fleet analytics across many accounts and subscriptions, which suits SaaS tenants.
- **AI and analytics.** Full-text search, vector data types and vector indexes (flat, quantized flat, DiskANN), sharded DiskANN aligned with partitions, hybrid search, RAG, durable agent memory (conversation state and semantic memory), and Fabric mirroring queried with T-SQL and Spark.

Where candidates lose points:

- Partition key questions. The "obvious" key (`/id`, a date, a low-cardinality category) is often wrong. Watch for 20 GB logical partition limits, hot writes and the need for in-partition transactions.
- RU arithmetic. A 1 KB point read costs about 1 RU. Writes and queries cost more, and indexing everything makes writes more expensive.
- Choosing strong consistency where session consistency is enough. Strong has multi-region costs and restrictions.
- Using a cross-partition query where a point read would do, or forgetting continuation tokens when paging.
- Studying the pre-October material: server-side stored procedures and triggers, Azure Synapse Link and the analytical store, or Data Factory moves. The change log removed or replaced these. Fabric mirroring now takes the analytical role.

## Study strategy

1. **Foundations.** Learn the account, database, container and item hierarchy, logical compared with physical partitions, RUs and the five consistency levels. Your AZ-204 prep covered some of this. Revisit it in depth.
2. **Model before code.** Take two realistic workloads, for example a multi-tenant SaaS order system and an agent memory store for chat sessions. Design containers, partition keys (including a hierarchical key such as tenant, user and session) and embed-or-reference choices. Then compute the RU cost of each main access pattern.
3. **SDK hands-on in C# or Python.** You may pick either, so your .NET background is a real advantage. Practise singleton `CosmosClient`, point reads, parameterised queries with paging, patch, bulk and transactional batch, ETag concurrency and TTL. Read the request charge on each response.
4. **Change feed.** Build one processor with a lease container and one pull-model reader. Try all versions and deletes mode.
5. **AI retrieval.** Add a vector embedding policy and DiskANN index, run `VectorDistance` queries, add full-text search, then a hybrid query. Wire it into a small RAG app and an agent memory store holding conversation state and long-term semantic memory.
6. **Operations.** Configure Entra ID RBAC with no keys, private endpoints, continuous backup with a restore, multi-region writes, diagnostic settings with KQL in Log Analytics, and alerts. Mirror a container into Fabric and query it with T-SQL and Spark.
7. **Official resources.** The certification page lists the learning paths and the [study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/dp-420). Use the [exam sandbox](https://aka.ms/examdemo) and the free practice assessment linked from the certification page.

How your background helps or misleads:

- **.NET.** C# is an allowed exam language and the .NET SDK is the most complete, so this is a strong advantage.
- **AZ-204 prep** taught the SDK basics, consistency levels and change feed, but at a shallower depth. Expect much more on partitioning and RU cost here.
- **Relational instincts** (normalise everything, join at query time) are the classic trap. Cosmos DB rewards denormalising for the dominant access pattern.
- **CKAD and Angular** are of little direct use here.

## Differences from related exams

- **DP-420 (2026) vs DP-420 (pre-October 2026).** The old Specialty covered data models, data distribution, integration (Synapse Link, Event Hubs, Functions), optimisation, and maintenance including DevOps and data movement. The new associate version keeps modelling, partitioning, change feed and performance, removes server-side JavaScript, data movement and DevOps, and adds a fifth of the exam on AI retrieval, agent memory and Fabric analytics.
- **DP-420 vs AI-200.** AI-200 uses Cosmos DB as one of three AI data stores (with PostgreSQL and Azure Managed Redis), at the level of "connect, query, embed, change feed". DP-420 goes deep on one store: partitioning theory, HPKs, all change feed modes, backup and multi-region, Fleet and Fabric.
- **DP-420 vs DP-800 (SQL AI Developer Associate).** DP-800 is the same idea (AI-enabled database development) for SQL Server, Azure SQL and SQL in Fabric: T-SQL, the relational vector type, and RAG from inside the database. DP-420 is the NoSQL, document-model counterpart.
- **DP-420 vs DP-900.** DP-900 only describes non-relational data and Cosmos DB APIs. DP-420 expects you to build with it.
- **DP-420 vs AWS.** AWS has no current database-specialty certification, so no counterpart is recorded. The closest material is DynamoDB design (partition and sort keys, GSIs, DynamoDB Streams), spread across the AWS developer (DVA-C03) and data engineer (DEA-C01) exams. Mapping: partition key to partition key, change feed to DynamoDB Streams, RUs to read and write capacity units, multi-region writes to Global Tables.

## Exam-day notes

- You have 100 minutes, with no labs expected. Partition-design case studies are the long items, so budget time for them.
- Do the RU and consistency reasoning on the whiteboard you are given. Write down the access patterns before you judge a partition key.
- Microsoft Learn is available. The SDK reference is useful for exact method names (patch operations, transactional batch), not for design questions.
- "Least RU", "single-digit-millisecond read" and "within one tenant" usually point to point reads and keys that keep related items in one logical partition.
- Breaks are not allowed inside a problem-and-solution set, and after any break you cannot return to questions you have already seen. Finish your marked items first.
