## Exam format

All facts below are as of 2026-10-24, taken from the [GitHub Advanced Security certification page](https://learn.microsoft.com/en-us/credentials/certifications/github-advanced-security/) and the [GH-500 study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/gh-500). Confirm them on those pages before you book.

- **Delivery.** A proctored exam scheduled through Pearson VUE from the Microsoft Learn page. Register with a personal Microsoft account.
- **Duration.** 100 minutes.
- **Question types and count.** Not published. The page says the exam may include interactive components. Expect scenario-based multiple-choice and multiple-select items about settings, alert screens, configuration files and CodeQL workflow YAML. The [exam sandbox](https://GHCertDemo.starttest.com) shows the interface.
- **Passing score.** 700 on a scale of 1–1000.
- **Price.** Not printed; it depends on the country or region where the exam is proctored and is shown when you schedule.
- **Languages.** English, Spanish, Portuguese (Brazil), Korean, Japanese. Localised versions lag English updates by about eight weeks, and that matters here: the July 2026 rewrite may reach non-English versions later.
- **Retakes.** You can retake 24 hours after a first failed attempt; see the [retake policy](https://learn.microsoft.com/en-us/credentials/support/retake-policy).
- **Validity and renewal.** The certification page says GitHub certifications are valid for **2 years**, and that GitHub is moving to Microsoft's recertification process. Certifications that expire before that process is available are extended by 6 months, and if yours has already expired the page says to contact learn@github.com for one exam voucher for your first renewal attempt. The study guide's generic table says associate certifications renew annually; trust the certification page.
- **Practice.** A Microsoft Learn practice assessment is linked from the certification page.

## What the exam really tests

The outline (skills measured as of July 2026) was significantly rewritten to follow GitHub's 2025 product split. "GitHub Advanced Security" is now sold as two products, **GitHub Secret Protection** and **GitHub Code Security**, and the exam calls the dependency features **supply chain security**. The titles of domains 2, 3 and 4 give the old names in brackets ("formerly secret scanning", "formerly Dependabot/Dependency Review", "formerly Code Scanning with CodeQL"), and older training materials and docs still use those names. You must be fluent in both sets of names.

Themes and depth:

- **The suites and their boundaries.** Which features belong to Secret Protection, which to Code Security, and which supply-chain features (dependency graph, Dependabot alerts) are free; what is available on public repositories compared with private repositories in GitHub Enterprise Cloud and GitHub Enterprise Server; and the Security Overview dashboards.
- **Secret Protection.** Enabling it at repository and organisation level, push protection (blocking a secret before it reaches the repository) compared with detecting secrets already pushed, validity checks, delegated bypass, alert recipients, exclusions and custom patterns.
- **Supply chain.** Dependency graph, SBOM export, Dependabot alerts, security updates and version updates (configured in `dependabot.yml` with grouping and update rules), auto-dismiss rules, EPSS-based prioritisation, and the Dependency Review action as a pre-merge check including licence checks.
- **Code Security.** Default setup compared with advanced setup for CodeQL, running it from GitHub Actions or another CI system, uploading SARIF from third-party tools, matrix builds across languages, scan frequency, data-flow paths in alerts, Copilot Autofix, and dismissing alerts with a reason.
- **Security operations.** CVE, CWE and GitHub Security Advisories, severity rules, security campaigns for fixing many alerts together, custom CodeQL query suites, and collaboration between developers, security managers and admins.
- **Administration.** Security configurations (enterprise and organisation defaults and how repositories inherit them), rulesets and enforcement, the security manager role, who can dismiss which alerts, and the APIs for rolling all of this out at scale.

Candidates lose points on product-name mapping, on which role can do what (repository admin, security manager, organisation owner, enterprise owner), on default compared with advanced CodeQL setup, and on the difference between a Dependabot *alert*, a Dependabot *security update* and a Dependabot *version update*. Note also that the outline is weighted towards operations and governance, not only switching features on.

Two oddities on the vendor page: the first skill group in domain 2 ("Manage and respond to Secret Protection alerts") is formatted as a top-level heading, and two bullets about CodeQL workflows and automation APIs appear under both 6.3 and 6.4. They are transcribed here exactly as printed.

## Study strategy

1. **Foundations first.** Learn the vocabulary of vulnerabilities (CVE, CWE, CVSS, EPSS, advisory databases, SBOM, SARIF) and the current product names. Read [About GitHub Advanced Security](https://docs.github.com/get-started/learning-about-github/about-github-advanced-security) before anything else.
2. **Hands-on on public repositories.** Code scanning, secret scanning with push protection and Dependabot are free on public repositories, so you can practise everything there except some enterprise settings. Make a public .NET repository with an old vulnerable NuGet package, an Angular app with outdated npm dependencies, and a test secret pattern. Turn on CodeQL default setup, then change to advanced setup and edit the generated workflow. Add the Dependency Review action to pull requests. Write a `dependabot.yml` with groups. Try to push a fake token to see push protection, and add a custom pattern.
3. **Upload third-party results.** Upload a SARIF file from another scanner through the `upload-sarif` action, to understand how external tools become code scanning alerts.
4. **Governance from the docs.** Read about security configurations, the security manager role, delegated bypass and security campaigns. These need an organisation, and on private repositories they need Secret Protection or Code Security licences, so study them from the docs if you have no such organisation.
5. **Official training.** Microsoft Learn paths [GitHub Advanced Security Part 1](https://learn.microsoft.com/en-us/training/paths/github-advanced-security/) and [Part 2](https://learn.microsoft.com/en-us/training/paths/github-advanced-security-2/), the module [Introduction to GitHub Advanced Security](https://learn.microsoft.com/en-us/training/modules/introduction-github-advanced-security/), and the GitHub Docs sections on [secret scanning](https://docs.github.com/code-security/secret-scanning), the [Dependabot quickstart](https://docs.github.com/code-security/getting-started/dependabot-quickstart-guide), [dependency review](https://docs.github.com/code-security/supply-chain-security/understanding-your-software-supply-chain/about-dependency-review) and [code scanning](https://docs.github.com/code-security/code-scanning/introduction-to-code-scanning/about-code-scanning). Finish with the practice assessment.

How your background helps or misleads: .NET and Angular give you real dependency trees (NuGet and npm) to practise on, and CodeQL supports C# and JavaScript/TypeScript. AZ-204 prep taught you to keep secrets in Key Vault, which is the remediation story behind secret alerts, but the exam asks about GitHub's alert lifecycle, not Azure. A common mistake for people from Azure DevOps is to assume "GitHub Advanced Security for Azure DevOps" behaves the same way; it is a different product with different setup steps. If you study GH-200 first, the CodeQL workflow questions become much easier.

## Differences from related exams

- **GH-500 vs CSSLP (ISC2 Certified Secure Software Lifecycle Professional).** CSSLP is vendor-neutral and process-focused: secure requirements, design, coding, testing, deployment and supply-chain management across the whole lifecycle, at a management level. GH-500 is one platform's implementation of those ideas (static analysis, secret detection, software composition analysis) at a configuration level. CSSLP asks why and when; GH-500 asks which setting, role or file.
- **GH-500 vs AZ-500 and SC-200.** AZ-500 secures Azure resources, and SC-200 runs a SOC with Microsoft Sentinel and Defender. Defender for Cloud can show GitHub security findings through its DevOps security feature, but neither exam tests CodeQL, push protection or Dependabot configuration.
- **GH-500 vs GH-200.** GH-200 secures the pipeline itself (token permissions, injection, action pinning, attestations). GH-500 uses the pipeline to find weaknesses in your code and dependencies.
- **GH-500 vs GH-100 (Administration).** GH-100 covers enterprise administration in general (authentication, permissions, policies). GH-500 goes deep only on security features and the roles that manage them.

## Exam-day notes

- Translate every old name to the new one as you read (secret scanning means Secret Protection; code scanning with CodeQL means Code Security; Dependabot and dependency review mean supply chain security). Options may mix both sets of names.
- "Prevent before it happens" points to push protection or Dependency Review. "Find what already exists" points to secret scanning alerts, code scanning alerts or Dependabot alerts.
- For "many repositories, consistently" questions, prefer security configurations, rulesets and security campaigns over changing repositories one by one.
- Dismissal questions usually want a recorded reason and a role with permission, not deleting the alert or ignoring it.
- Pace yourself against the 100-minute clock; the question count is not published. Spend any time left re-reading questions about roles and plan availability. Microsoft's [exam scoring page](https://learn.microsoft.com/en-us/credentials/certifications/exam-scoring-reports) says there is no penalty for guessing, so answer every item.
