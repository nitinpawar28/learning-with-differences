## Exam format

All facts below are as of 2026-10-24, taken from the [GitHub Copilot certification page](https://learn.microsoft.com/en-us/credentials/certifications/github-copilot/) and the [GH-300 study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/gh-300). Confirm them on those pages before you book.

- **Delivery.** A proctored exam scheduled through Pearson VUE from the Microsoft Learn certification page. Register with a personal Microsoft account so your records stay with you if you change employer.
- **Duration.** 100 minutes.
- **Question types and count.** Not published. The page says the exam may include interactive components. Expect mostly single-answer and multiple-answer items about features, settings and scenarios. Try the [exam sandbox](https://GHCertDemo.starttest.com) to see the interface.
- **Passing score.** 700 on a scale of 1–1000.
- **Price.** Not printed; it depends on the country or region where the exam is proctored and is shown when you schedule.
- **Languages.** English, Spanish, Portuguese (Brazil), Korean, Japanese. Localised versions are updated about eight weeks after English. If your language is not offered you can request 30 extra minutes.
- **Retakes.** You can retake 24 hours after a first failed attempt; see the [retake policy](https://learn.microsoft.com/en-us/credentials/support/retake-policy) for later attempts.
- **Validity and renewal.** The certification page says GitHub certifications are valid for **2 years**, and that GitHub is moving to Microsoft's recertification process. Certifications that expire before that process is available are extended by 6 months, and if yours has already expired the page says to contact learn@github.com for one exam voucher for your first renewal attempt. The generic table in the study guide says associate certifications renew annually; trust the certification page and check again near your expiry date.
- **Practice.** A Microsoft Learn practice assessment is linked from the certification page.

## What the exam really tests

The current outline is "skills measured as of August 7, 2026". The change log lists only minor changes compared with the previous version, in the IDE, features-and-capabilities and safeguards areas. Note one error on the page: the "skills at a glance" list shows "GitHub Copilot features (25–30%)" twice, but the detailed outline has six domains, and only six are transcribed here.

The exam is a **product-knowledge exam about an AI tool**, with a responsible-AI layer on top:

- **Features and where they live (25–30%, the largest domain).** Inline suggestions, Copilot Chat, Copilot CLI, agent mode, Copilot Edits, MCP servers, agent sessions and sub-agents, Copilot code review, pull request summaries, Copilot Spaces, Spark, instruction files and prompt files. You need to know which feature fits a task and which surface (IDE, github.com, terminal) provides it. Copilot CLI has its own skill group: installation, commands, interactive and session use, and generating scripts.
- **Administration.** Organisation-wide policies, enabling code review policies, controlling feature availability across IDEs and github.com, audit log events, and managing seats (subscriptions) through the REST API. Questions often depend on which plan (Free, Pro, Pro+, Business, Enterprise) includes a feature or policy, so learn the [plans page](https://docs.github.com/copilot/about-github-copilot/plans-for-github-copilot).
- **How Copilot works with data.** How the prompt is built from context, what leaves the editor, the proxy filtering and post-processing that happen before a suggestion is returned, the suggestion lifecycle, and what is and is not retained.
- **Prompt engineering.** Zero-shot compared with few-shot prompting, how context is chosen (open files, selections, chat participants and variables), and chat history.
- **Productivity use cases.** Refactoring, documentation, tests and edge cases, sample data, legacy modernisation, and security and performance suggestions.
- **Privacy and safeguards.** Content exclusions (what they do and where they do not apply), the filter for suggestions matching public code, output ownership, and troubleshooting missing suggestions.

Candidates lose points on plan and policy details (which setting is available at which level, and who can change it), on content-exclusion scope and limits, and on treating every feature as available everywhere. A second trap is the responsible-AI domain: the "correct" answer is almost always to validate output, keep a human reviewer, and not trust generated code by default.

## Study strategy

1. **Foundations first.** Learn the plans and features page and the data-handling pages before the feature tour, because many questions start with "an organisation on plan X wants...". Then read the [prompt engineering guide for Copilot Chat](https://docs.github.com/copilot/using-github-copilot/copilot-chat/prompt-engineering-for-copilot-chat) and [content exclusion](https://docs.github.com/copilot/managing-copilot/configuring-and-auditing-content-exclusion) pages.
2. **Hands-on in your own stack.** Use Copilot in Visual Studio or VS Code on a .NET API and an Angular app: inline completion, chat with selected code, agent mode on a multi-file change, a `.github/copilot-instructions.md` file and a reusable prompt file, an MCP server added to your editor, and Copilot code review on a pull request. Install Copilot CLI and use it in an interactive session.
3. **Admin side.** If you can, start a Copilot Business trial in a test organisation to see the policy pages, content exclusions and audit log. Otherwise read the admin docs carefully, because this is where hands-on-only users are weakest.
4. **Official training.** Microsoft Learn paths [GitHub Copilot Fundamentals Part 1](https://learn.microsoft.com/en-us/training/paths/copilot/) and [Part 2](https://learn.microsoft.com/en-us/training/paths/gh-copilot-2/), plus the modules [Responsible AI with GitHub Copilot](https://learn.microsoft.com/en-us/training/modules/responsible-ai-with-github-copilot/), [Developer use cases for AI](https://learn.microsoft.com/en-us/training/modules/developer-use-cases-for-ai-with-github-copilot/) and [Develop unit tests using GitHub Copilot tools](https://learn.microsoft.com/en-us/training/modules/develop-unit-tests-using-github-copilot-tools/). The [GitHub Trust Center](https://github.com/trust-center) covers data handling. Finish with the practice assessment.

How your background helps or misleads: your .NET and Angular work gives you natural material for the productivity and testing domains, and AZ-204 prep taught you to treat any generated SDK snippet with suspicion. AZ-900 and CKAD add little here. The trap is assuming that daily use is enough. Developers who use Copilot every day usually miss the plan matrix, organisation policies, audit events and the data-flow pipeline, which together are a large share of the exam. Also, Copilot features are renamed and moved often: learn the names used in the current docs, not the names you remember.

## Differences from related exams

- **GH-300 vs GH-600 (Agentic AI Developer).** GH-300 asks "can you use and administer Copilot well?", including agent mode and MCP as features. GH-600 asks "can you design, supervise, evaluate and govern agents in the SDLC?": planning compared with execution, autonomy levels, memory, multi-agent orchestration, and failure analysis. Take GH-300 first; GH-600's audience profile assumes Copilot, MCP and custom-agent experience.
- **GH-300 vs AI-901 and AIF-C01.** The Azure and AWS AI fundamentals exams are about cloud AI services and general AI concepts. GH-300 is about one developer tool and how it handles your code. The only real overlap is responsible AI and prompt basics. There is no AWS exam about a coding assistant, which is why no counterpart is listed.
- **GH-300 vs GH-900.** GH-900 mentions Copilot as one GitHub product. GH-300 goes into plans, policies, data flow and feature details.
- **GH-300 vs AB-100 and the Microsoft 365 Copilot exams.** Those cover Microsoft 365 Copilot and business agents. GitHub Copilot is a separate product with its own plans and admin model. Do not mix their policy names.

## Exam-day notes

- Read plan words carefully ("Business", "Enterprise", "individual"). The plan often decides the answer.
- When an option says Copilot "guarantees" secure, correct or licence-clean code, it is almost certainly wrong. Look for the option that includes validation and human review.
- Content-exclusion questions: remember that exclusions are configured by repository, organisation or enterprise admins and do not cover every Copilot surface. Check the current docs for exactly which features honour them.
- Know which surface owns a feature: code review and pull request summaries are on github.com, Copilot CLI is in the terminal, agent mode and Edits are in the IDE.
- Mark uncertain items for review and return to them. The question count is not published, so check your pace against the 100-minute clock early. Microsoft's [exam scoring page](https://learn.microsoft.com/en-us/credentials/certifications/exam-scoring-reports) says there is no penalty for guessing, so answer every item.
