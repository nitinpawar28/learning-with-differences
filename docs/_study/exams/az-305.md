## How the credential works

AZ-305 is the only exam for **Microsoft Certified: Azure Solutions Architect Expert**, but passing it is not enough on its own. The [certification page](https://learn.microsoft.com/en-us/credentials/certifications/azure-solutions-architect/) says that to earn the credential you must also hold **Microsoft Certified: Azure Administrator Associate** (AZ-104). You can sit AZ-305 first, but the expert certification is awarded only once both conditions are met. In this library's roadmap AZ-305 is stage 5, after AZ-104 and the security and networking work in between.

## What the exam really tests

Every bullet starts with *recommend*, *specify* or *evaluate*. The exam gives you requirements, usually several conflicting ones, and asks for the design that meets all of them at the lowest cost or complexity. It assumes you already know how each service is configured (that's AZ-104) and tests whether you can choose between services.

- **Identity, governance and monitoring (25–30%).** Where logs go and how they are routed: Log Analytics workspaces, diagnostic settings, Event Hubs for export, storage for archive. Then Azure Monitor and Application Insights for monitoring. On the identity side: authentication choices (Microsoft Entra ID, B2B, external ID, hybrid identity), authorisation for Azure resources (RBAC, managed identities, Privileged Identity Management) and for on-premises resources (for example application proxy or Entra Domain Services), and Key Vault for secrets, certificates and keys. On governance: management group, subscription and resource group structure with a tagging strategy, compliance with Azure Policy and initiatives, and identity governance (access reviews, entitlement management).
- **Data storage (20–25%).** Relational data: Azure SQL Database, SQL Managed Instance or SQL Server on VMs, the purchasing models and service tiers, scaling (elastic pools, read replicas, Hyperscale) and data protection. Semi-structured and unstructured data: Cosmos DB versus Table storage versus Blob Storage, access tiers and redundancy trade-offs. Integration and analysis: Data Factory, and the analytics services named in the documentation.
- **Business continuity (15–20%).** Mapping RTO and RPO to Azure Backup, Azure Site Recovery, geo-replication and failover groups. High availability for compute (availability zones, scale sets, multi-region), for relational data (zone-redundant and business-critical tiers, auto-failover groups) and for storage (ZRS, GZRS, Cosmos DB multi-region writes).
- **Infrastructure (30–35%).** Compute choice (VMs, AKS, Container Apps, App Service, Functions, Batch). Application architecture: messaging (Service Bus, Storage queues) versus events (Event Grid, Event Hubs), API Management, Azure Managed Redis caching, App Configuration, and automated deployment. Migration through the Cloud Adoption Framework and Azure Migrate, Database Migration Service, Data Box. Networking: internet connectivity, hybrid connectivity (VPN, ExpressRoute), network performance and security, and load balancing and routing (Load Balancer, Application Gateway, Front Door, Traffic Manager).

Where candidates lose points: choosing a technically correct service that costs more than needed, ignoring one requirement hidden in the case study (a region restriction, a "no code changes" rule, a licensing constraint), confusing messaging with eventing, and picking a regional load balancer for a global requirement.

## Study strategy

1. **Hold AZ-104 first.** The credential requires it, and design answers are much easier once you have configured the services.
2. **Learn the decision trees.** The Azure Architecture Center (linked in the study guide's documentation list, with "Browse Azure Architectures") publishes decision guides for compute, data stores, load balancing and messaging. Learn them until you could redraw them from memory. The domain weights come straight from those choices.
3. **Well-Architected and Cloud Adoption Framework.** The audience profile names both. Know the five Well-Architected pillars and their trade-offs, and the CAF phases used in migration questions.
4. **Business continuity by numbers.** For each data and compute service, write down the SLA-relevant options, the RPO and RTO each one achieves, and what it costs.
5. **Practise on case studies.** Read a requirements page, list every constraint, then design. The free practice assessment on the exam page is the closest official example.

Official resources: the [AZ-305T00 course](https://learn.microsoft.com/en-us/training/courses/az-305t00) and its matching self-paced learning paths, the free practice assessment, the Exam Readiness Zone videos, and the study guide's documentation links (Azure documentation, *Architect infrastructure operations in Azure*, Azure Architecture Center, *Browse Azure Architectures*).

How your background helps or misleads:

- **AZ-204 preparation** is a real advantage in the application architecture group (messaging, events, API Management, caching, App Configuration) and in the compute choices. Don't drop into implementation detail: "which SDK call" won't appear, while "which service and tier" will.
- **CKAD preparation** helps you judge when AKS is worth its operational cost. The exam often prefers Container Apps or App Service when the requirement is "minimise management".
- **.NET and Angular background** helps you read the application scenarios quickly, for example a .NET web front end with a SQL back end being migrated.
- **AWS knowledge** carries over to design reasoning. The trap is assuming AWS service boundaries: Azure SQL tiers are not RDS instance classes, and Front Door combines things that AWS splits between CloudFront and Global Accelerator.

## Differences from related exams

- **AZ-305 vs SAP-C03 (AWS Certified Solutions Architect – Professional).** Both are professional-level design exams built on long scenarios. The AWS professional exam is broader and harder to finish in time. Its predecessor SAP-C02 was organised around organisational complexity (multi-account), designing new solutions, continuous improvement of existing ones, and accelerating migration and modernisation. Its questions are long, with several plausible answers (see the SAP-C03 page in this library for the current outline). AZ-305 is narrower (four domains), leans more on identity and governance, and puts its long reading in case studies rather than in every question. SAP-C03 has no prerequisite. AZ-305 needs AZ-104 for the credential.
- **AZ-305 vs SAA-C03.** SAA-C03 is the associate design exam. AZ-305 asks for similar trade-offs at a higher level, with more identity, governance and migration.
- **AZ-305 vs AZ-104.** The services are the same, but the question changes from *how do I configure this* to *which one, and why*.
- **AZ-305 vs AZ-700 and AZ-500.** AZ-305's networking and security are design-level recommendations. The specialist exams expect implementation detail (gateway SKUs, BGP, firewall policy rules, Defender configuration).

## Exam-day notes

- Case studies come first or as separate sections, and you can't go back after leaving one. Read the requirements tab twice and note every constraint before you look at the questions.
- Eliminate answers that break a stated constraint. Among the rest, choose the cheapest and simplest one that meets every requirement. "Over-engineered" is a wrong answer on this exam.
- Watch keywords: *global* (Front Door or Traffic Manager), *HTTP layer 7* (Application Gateway or Front Door), *no code changes* (rehost on IaaS, or SQL Managed Instance for compatibility), *least administrative effort* (PaaS).
- Use Microsoft Learn access only for a specific limit or tier feature.
