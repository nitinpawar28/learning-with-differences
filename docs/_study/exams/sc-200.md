## What the exam really tests

SC-200 is the SOC analyst exam. It checks that you can run the Microsoft security operations stack day to day: **Microsoft Defender XDR** (the unified Defender portal over Defender for Endpoint, Office 365, Identity and Cloud Apps), **Microsoft Sentinel** (now described as a SIEM *and platform*, with a data lake tier, Sentinel Graph and an MCP server), Defender for Cloud workload protection alerts, Entra ID Protection risk signals, and Microsoft Purview signals.

The weighting tells you where the effort goes:

- **Manage a security operations environment (40–45%).** This is the engineering half of the job. It covers automation (Defender XDR notifications, automated investigation and response, automatic attack disruption, Defender for Endpoint device groups and automation levels, Sentinel automation rules and playbooks), Sentinel configuration (roles, retention across Analytics, Data lake and XDR tiers, workbooks, SOC optimisation), ingestion (AMA-based Windows Security Events, WEF, Syslog and CEF via AMA, Azure activity logs through Azure Policy and diagnostic settings, threat indicators, custom tables) and detections (XDR custom detections, Sentinel scheduled, NRT, threat intelligence and ML rules, MITRE ATT&CK coverage, anomalies).
- **Respond to security incidents (35–40%).** Investigating and remediating incidents from each Defender product, Entra ID, Purview and Sentinel. It includes using embedded Microsoft Security Copilot (the outline's "agentic AI"), multi-stage and lateral-movement attacks, case management, Defender for Endpoint device timelines and live response, and Microsoft 365 investigations with Purview Audit, eDiscovery Content search and Microsoft Graph activity logs.
- **Perform threat hunting (20–25%).** KQL in Advanced Hunting and Sentinel, choosing the right table, threat analytics, hunting graphs and blast radius, Sentinel Graph, hunting queries, KQL jobs and summary rules in the data lake, and notebooks connected to the Sentinel MCP Server.

Scenarios are operational: "An alert fires on a device; what action isolates it but still allows collection of an investigation package?" or "Which connector and rule type ingest and detect X with the lowest latency?" Expect KQL snippets where you complete or interpret a query.

Points are lost on:

- **Where a setting lives.** Defender XDR versus Sentinel versus Defender for Endpoint settings pages; automation rules versus playbooks; analytics rules versus custom detections.
- **Ingestion details.** The legacy Log Analytics agent is gone. Know data collection rules with the Azure Monitor Agent, when WEF is still needed, and which tier (analytics or data lake) a table should land in for cost versus query needs.
- **KQL fluency.** `where`, `project`, `summarize`, `join`, `extend`, `bin()` and time filters, and knowing the core tables (`DeviceProcessEvents`, `DeviceNetworkEvents`, `EmailEvents`, `IdentityLogonEvents`, `SigninLogs`, `SecurityEvent`, `AuditLogs`).
- **New platform features.** The data lake, Sentinel Graph, summary rules and the MCP server are recent; older third-party material does not cover them.

## Study strategy

1. **Foundations.** If SC-900 is done, re-skim its Defender XDR and Sentinel sections. Then learn KQL properly: Microsoft's KQL tutorials and the Log Analytics demo environment are the fastest route.
2. **Defender XDR first.** Stand up a Microsoft 365 E5 trial (or developer tenant), onboard a test Windows VM to Defender for Endpoint, run the simulated attacks that the Defender for Endpoint documentation provides, and work the resulting incidents end to end in the Defender portal.
3. **Sentinel second.** Create a Log Analytics workspace, enable Sentinel, deploy content hub solutions, connect Entra ID, Azure Activity and Defender XDR, add a Windows VM through a DCR, and write a scheduled rule, an NRT rule, an automation rule and a Logic Apps playbook. Move a table to the data lake tier and run a KQL job against it.
4. **Hunting last.** Build Advanced Hunting queries, a custom detection from a query, a hunting graph, and a notebook session. Map your rules to MITRE ATT&CK in the Sentinel MITRE page.

Official resources: the SC-200 self-paced learning paths and instructor-led course on the [certification page](https://learn.microsoft.com/en-us/credentials/certifications/security-operations-analyst/), the free practice assessment, the exam sandbox, the SC-200 exam prep videos, and the product documentation linked from the [study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/sc-200).

How your background helps or misleads:

- **AZ-204 prep**: Azure Monitor, Application Insights and Log Analytics queries carry over, and so does Logic Apps (Sentinel playbooks are Logic Apps). Your KQL from App Insights is a real head start.
- **.NET background**: Python or C# notebooks feel natural, but the exam cares about the hunting logic, not the code.
- **CKAD prep**: Defender for Containers alerts appear only through Defender for Cloud workload protection. Kubernetes detail is not tested here.
- **AWS knowledge** can mislead. GuardDuty plus Security Hub plus Detective is a loose AWS analogue, but Microsoft's model is one incident queue in the Defender portal with Sentinel unified into it. Do not look for an "aggregator" product.

## Differences from related exams

- **SC-200 vs SC-500.** SC-500 *configures* the platform security (it sets up Sentinel workspaces, connectors, retention, Defender for Cloud plans). SC-200 *operates* it: triage, investigation, hunting and detection engineering. There is overlap on Sentinel ingestion, but SC-200 goes much deeper on XDR, KQL and incident response, and SC-500 much deeper on Azure resource hardening.
- **SC-200 vs SC-100.** SC-100 designs the security-operations capability (XDR plus SIEM, SOAR, logging strategy, MITRE coverage) as one of many areas. SC-200 is the hands-on depth behind that one area.
- **SC-200 vs SCS-C03 (AWS Certified Security – Specialty).** The AWS exam's threat detection and incident response domains (GuardDuty, Security Hub, Detective, CloudTrail, Athena queries) are the nearest AWS analogue, but SCS-C03 also covers IAM, data protection and infrastructure security, so it is broader and shallower on SOC work. AWS has no dedicated SOC-analyst exam.
- **SC-200 vs CS0-004 (CompTIA CySA+).** CySA+ is the vendor-neutral SOC analyst exam: vulnerability management, threat intelligence, log analysis and incident response process. It is better for "why"; SC-200 is entirely "how, in Microsoft tools".
- **SC-200 vs SC-900.** SC-900 asks what Sentinel is; SC-200 asks you to write the rule that fires in it.

## Exam-day notes

- 100 minutes for roughly 40–60 items, with case studies and possible interactive tasks. Budget about 1.5 minutes per standard question and bank time for case studies.
- Problem–solution sets ("Does this solution meet the goal?") are announced on screen, and once you answer one you cannot go back to it. Microsoft's duration page also says you cannot take a break in the middle of one. Decide each proposed solution on its own merits, because more than one can be correct.
- The Microsoft Learn lookup is good for confirming a table name or a connector requirement. Do not use it to learn a topic mid-exam.
- Watch for retired terminology in distractors: the Log Analytics agent (MMA), the old Microsoft 365 Defender portal, and "Azure Sentinel".
- For KQL items, check the time window and the `summarize ... by` column first; most wrong options differ there.
