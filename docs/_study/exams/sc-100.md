## What the exam really tests

SC-100 is a design-and-evaluate exam. The verbs are "design", "evaluate", "specify" and "recommend", not "configure". You are given an organisation's situation, constraints and goals, usually in a long case study, and asked which strategy, framework alignment or Microsoft capability best meets them.

The four areas:

- **Best practices and priorities (20–25%).** Ransomware resiliency and BCDR (secure backup, prioritising privileged access), security updates; alignment with the **Microsoft Cybersecurity Reference Architectures (MCRA)** and the **Microsoft Cloud Security Benchmark (MCSB)**, including AI solutions; the **Zero Trust adoption framework**; the **Cloud Adoption Framework (CAF)** and **Well-Architected Framework (WAF)** for security and governance; secure AI adoption; Azure landing zones; DevSecOps.
- **Security operations, identity and compliance (25–30%).** XDR plus SIEM detection and response, centralised logging with Purview Audit, hybrid and multicloud monitoring, SOAR with Sentinel and Defender XDR, incident response and hunting workflows, MITRE ATT&CK coverage (Enterprise, Mobile and ICS). Identity: **Entra Agent ID** for agent identities, access to SaaS/PaaS/IaaS/hybrid/multicloud, Entra ID in hybrid and multicloud, B2B and decentralised identity, Conditional Access with CAE and protected actions, AD DS hardening, secrets and keys. Privileged access: the enterprise access model, PIM, entitlement management, access reviews, AD DS resilience, tenant administration, cloud infrastructure entitlement management, privileged access workstations. Compliance: translating requirements into controls with Purview, Azure Policy and Defender for Cloud.
- **Infrastructure (25–30%).** Posture management with Defender for Cloud and MCSB, Secure Score, multicloud via Azure Arc, Defender EASM, Microsoft Security Exposure Management (attack paths, initiatives); endpoints, mobile, IoT and OT (Defender for IoT), security baselines, Windows LAPS; SaaS/PaaS/IaaS baselines, web, containers and orchestration, Azure AI services; network security and Security Service Edge with **Microsoft Entra Internet Access** and **Private Access**.
- **Applications and data (20–25%).** Microsoft 365 posture (Secure Score, Defender for Office 365, Defender for Cloud Apps, Intune, Purview, Microsoft 365 Copilot data controls); application security (portfolio posture, threat modelling, secure SDLC, workload identities, API management, WAF); data security (discovery and classification, threat priorities, encryption with Key Vault and infrastructure encryption, data used in AI workloads, Azure SQL, Synapse, Cosmos DB, Storage, Defender for Storage and Databases).

Points are lost on:

- **Choosing the framework.** MCRA (the capability map), MCSB (the control set Defender for Cloud measures), Zero Trust adoption framework (business scenarios and rollout), CAF (adoption and governance process) and WAF (workload-level design pillars). Questions often ask which one a requirement belongs to.
- **Order of priorities.** Microsoft's ransomware guidance prioritises recovery readiness and privileged access first. Answers that start with perimeter controls are usually wrong.
- **Breadth.** You must know enough about every product family (Entra, Defender XDR, Defender for Cloud, Sentinel, Purview, Intune, Entra Suite, Security Exposure Management) to choose between them, even outside your specialist area.
- **Case-study discipline.** Requirements are scattered across tabs (existing environment, business requirements, technical requirements, constraints). Missing a single constraint ("must not deploy agents to OT devices") flips the answer.

## Study strategy

1. **Foundations first.** Hold, or be at the level of, one of the qualifying associates. For this roadmap, SC-500 (core, stage 4) is the natural one; SC-200 or SC-300 also qualify.
2. **Read the frameworks.** Work through MCRA, MCSB, the Zero Trust guidance and adoption framework, the CAF secure and govern methodologies, the WAF security pillar, Azure landing zones and Microsoft's ransomware protection guidance. These are the backbone of domain 1 and colour the whole exam.
3. **Fill your weakest product family.** If you come from SC-500, study SC-200's SOC workflows and SC-300's governance. If you come from SC-300, study Defender for Cloud and Sentinel. Everyone needs the Microsoft 365 side (Defender for Office 365, Intune, Purview, Copilot data controls).
4. **Practise case studies.** Take the free practice assessment. Then write one-page designs for invented organisations: a hybrid manufacturer with OT, a multicloud SaaS company, a regulated bank adopting Microsoft 365 Copilot and AI agents.
5. **Hands-on is secondary but useful.** Exposure Management attack paths, Defender for Cloud multicloud connectors, Entra Internet and Private Access, and Entra Agent ID are new enough that a quick lab makes them concrete.

Official resources: the SC-100 learning paths and the instructor-led course "Microsoft Cybersecurity Architect" listed on the [exam page](https://learn.microsoft.com/en-us/credentials/certifications/exams/sc-100/), the free practice assessment, the exam sandbox, the SC-100 exam prep videos, and the documentation linked from the [study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/sc-100).

How your background helps or misleads:

- **AZ-900 and AZ-204 prep** give you Azure and app-identity grounding; the "Design solutions for securing applications" group (workload identities, API Management, WAF, secure SDLC) will feel closest to your developer experience.
- **.NET and Angular background** helps with threat modelling and DevSecOps questions. The trap is answering as an implementer: SC-100 wants the strategic option ("adopt a full lifecycle application security strategy aligned to CAF"), not a code-level fix.
- **CKAD prep** helps with "specify requirements for containers and orchestration", where you name the controls (image provenance, admission policy, network policy, runtime protection) rather than configure them.
- **Architect ambitions**: AZ-305 is the Azure design counterpart. Its habit of designing to requirements and constraints transfers directly; its product depth does not.
- **AWS knowledge** helps on multicloud items, where Defender for Cloud, Arc and Entra must cover AWS accounts too. Know which Microsoft tool reaches into AWS and how.

## Differences from related exams

- **SC-100 vs SC-500, SC-200 and SC-300.** The associates are implementation depth in one area each (cloud and AI engineering, SOC, identity). SC-100 covers all of them plus Microsoft 365, endpoints, OT and data at design depth. You need breadth across the associates and depth in none of them.
- **SC-100 vs AZ-305 (Azure Solutions Architect Expert).** AZ-305 designs whole Azure solutions (compute, data, networking, identity, BCDR) with security as one consideration. SC-100 designs security only, across Azure, Microsoft 365, hybrid and multicloud. AZ-305 is Azure-centric; SC-100 is Microsoft-security-portfolio-centric.
- **SC-100 vs SCS-C03 (AWS Certified Security – Specialty).** AWS has no security-architect expert exam; SCS-C03 is the nearest. It is hands-on specialty depth on AWS services and multi-account design. SC-100 is broader (identity, SOC, endpoint, OT, Microsoft 365, data) and more strategic, with framework alignment (MCRA, MCSB, CAF, Zero Trust) that SCS-C03 does not test.
- **SC-100 vs ISSAP and CCSP.** ISSAP (ISC2's architecture concentration) and CCSP (cloud security) are vendor-neutral and test architecture principles, governance and risk without products. SC-100 tests the same kind of thinking expressed through Microsoft products. Doing SC-100 first gives you concrete examples; doing CCSP or ISSAP first gives you the reasoning SC-100 leaves implicit.
- **SC-100 vs SC-900.** SC-900 is the glossary; SC-100 is the decision-maker using all of it.

## Exam-day notes

- Expect case studies. Read the requirements and constraints tabs first, note them on your scratch board, then answer the questions. Revisit the tabs for each question; do not rely on memory.
- The on-screen instructions for each case study say whether you can return to it. Normally you can move between its questions until you leave the case study, and then you cannot go back. Finish and review before moving on.
- When two options both work, choose the one that aligns with the named framework or Zero Trust principle in the scenario, and that minimises complexity and new products.
- Look for "evaluate" questions that ask whether a proposed design *meets* a goal. Check every stated requirement, not just the headline one.
- Microsoft Learn is available, but architect questions rarely hinge on a single setting. Save the time for case-study reading.
