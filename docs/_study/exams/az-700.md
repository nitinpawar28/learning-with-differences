## What the exam really tests

AZ-700 is a deep networking specialist exam. The verbs mix *design* and *implement*, so you need to know both which service to use and the exact objects and settings that make it work.

- **Core infrastructure (25–30%).** Address planning and segmentation, subnet sizing for services that need dedicated or delegated subnets (gateway subnet, AzureFirewallSubnet, AzureBastionSubnet, Application Gateway, VNet-integrated PaaS), public IP prefixes and bring-your-own-IP (custom IP prefix). Name resolution inside VNets, public and private DNS zones, VNet links and Azure DNS Private Resolver. Peering with gateway transit, service chaining, Azure Virtual Network Manager, UDRs, forced tunnelling, Azure Route Server and NAT Gateway. Monitoring with Network Watcher, Azure Monitor for Networks, DDoS Protection, and Defender for Cloud (secure score, attack path analysis, Cloud Security Explorer).
- **Connectivity (20–25%).** Site-to-site VPN (SKUs, active-active, policy-based versus route-based, local network gateways, IPsec/IKE policy, Azure Extended Network). Point-to-site VPN (tunnel types, certificate, RADIUS and Microsoft Entra authentication, client profiles, Always On VPN, Azure Network Adapter). ExpressRoute (connectivity models, SKUs and tiers, private versus Microsoft peering, Global Reach, FastPath, ExpressRoute Direct, route advertisement, encryption, BFD and troubleshooting). Virtual WAN (SKUs, hubs, scale units, hub routing, third-party NVAs).
- **Application delivery (15–20%).** Azure Load Balancer (SKUs, public versus internal, regional versus cross-region, Gateway Load Balancer, rules, inbound NAT, outbound SNAT rules), Traffic Manager, Application Gateway (autoscale, listeners, rules, HTTP settings, probes, TLS, rewrites) and Front Door (tiers, routing, origins, caching, end-to-end TLS, rules engine, and Private Link to origins).
- **Private access (10–15%).** Private endpoints and Private Link service, the DNS integration that makes them work (privatelink zones, on-premises resolution through Private Resolver or forwarders), service endpoints and service endpoint policies.
- **Network security (15–20%).** NSGs and ASGs, virtual network flow logs (the successor to NSG flow logs, which Microsoft is retiring), IP flow verify, Bastion access rules, Virtual Network Manager security admin rules, Azure Firewall SKUs, rules and Firewall Manager policies, secured virtual hubs, and WAF on Application Gateway and Front Door (detection versus prevention, rule sets, policy association).

Where candidates lose points: private endpoint DNS (the endpoint works but name resolution still returns the public IP), choosing between Load Balancer, Application Gateway, Front Door and Traffic Manager (layer 4 versus layer 7, regional versus global), ExpressRoute peering and SKU combinations, which gateway SKUs support which features, and asymmetric routing after adding a UDR or a firewall.

## Study strategy

1. **Foundations first.** Revise IP subnetting, CIDR, BGP basics, DNS resolution order and TLS termination. Then build the AZ-104 networking set (VNets, peering, NSGs, UDRs, load balancer) before anything hybrid.
2. **Hub-and-spoke lab.** Build a hub with Azure Firewall and a spoke with a UDR that forces traffic through the firewall, then add a private endpoint for a storage account and make DNS resolve it from the spoke and from a "simulated on-premises" VNet through DNS Private Resolver. This one lab covers about a third of the outline.
3. **Gateways.** A VPN gateway takes a long time to deploy and costs money by the hour, so script it (Bicep or CLI) and delete it straight after. Do a VNet-to-VNet or site-to-site connection with a custom IPsec policy and a point-to-site connection with Microsoft Entra authentication. ExpressRoute and Virtual WAN are hard to lab on your own. Study them from the documentation and diagrams.
4. **Application delivery.** Put the same backend behind Application Gateway with WAF and behind Front Door Premium with a Private Link origin, and compare.
5. **Monitoring.** Use Network Watcher (connection troubleshoot, next hop, IP flow verify), enable VNet flow logs and query them.

Official resources: the [AZ-700T00 course](https://learn.microsoft.com/en-us/training/courses/az-700t00) and its self-paced paths, the free practice assessment and *Exam AZ-700 prep videos* on the certification page, and the long documentation list in the study guide (VPN, ExpressRoute, Virtual WAN, Route Server, Load Balancer, Application Gateway, Front Door, Traffic Manager, NAT Gateway, Azure Firewall, WAF, Private Link, private endpoints, Azure DNS, Azure Monitor).

How your background helps or misleads:

- **AZ-900 and AZ-104 preparation** cover only the first layer. AZ-700 assumes you know NSGs and peering cold.
- **AZ-204 preparation** helps with App Service VNet integration and private endpoints from the application side, but not with gateways or BGP.
- **CKAD preparation** gives you the service, ingress and network policy ideas, but AKS networking is not in this outline. Don't expect CNI questions.
- **AWS knowledge** maps reasonably: VPC to VNet, Transit Gateway to Virtual WAN or a hub with Virtual Network Manager, Direct Connect to ExpressRoute, PrivateLink to Private Link, Route 53 Resolver to DNS Private Resolver. The traps: Azure subnets span all zones in a region, Azure reserves five addresses per subnet, NSGs attach at subnet *and* NIC level, and Azure has no direct equivalent of a security group referenced by ID (ASGs are the closest).

## Differences from related exams

- **AZ-700 vs ANS-C01 (AWS Certified Advanced Networking – Specialty).** The closest match on the other cloud. ANS-C01 is a specialty exam at a higher level. It puts more weight on hybrid design across many accounts, on BGP and Direct Connect detail, and on network automation. AZ-700 is an associate exam with more "configure this object" questions and more application delivery (Front Door, Application Gateway, WAF).
- **AZ-700 vs AZ-104.** AZ-104 networking is a subset: VNets, peering, UDRs, NSGs, Bastion, endpoints, DNS and load balancers. AZ-700 adds hybrid connectivity, global and layer 7 delivery, firewalls and WAF, Route Server, Private Resolver and Virtual Network Manager, at implementation depth.
- **AZ-700 vs AZ-305.** AZ-305 asks for a network recommendation in one of four design domains. AZ-700 asks you to size the gateway, write the route and pick the SKU.
- **AZ-700 vs AZ-500.** Both include Azure Firewall, WAF and NSGs. AZ-500 sees them as security controls alongside identity, Key Vault and Defender. AZ-700 sees them as part of the routing and delivery design.

## Exam-day notes

- Draw it out. For any routing or DNS question, sketch the hubs, spokes, gateways and resolvers on the whiteboard or scratch sheet before reading the options.
- Remember what wins in Azure routing: the longest prefix match first, and then, for identical prefixes, UDRs beat BGP, which beats system routes.
- For load-balancing questions, ask three things in order. Is it global or regional? Is it layer 4 or layer 7? Is it HTTP(S)? The service follows from the answers.
- SKU questions are where a quick Microsoft Learn lookup pays off. Don't spend it on concepts.
