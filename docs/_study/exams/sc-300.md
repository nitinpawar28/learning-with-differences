## What the exam really tests

SC-300 is the Microsoft Entra administrator exam. It is more hands-on than its "administrator" label suggests: you configure the tenant, users and groups, external collaboration, hybrid sync, authentication methods, Conditional Access, ID Protection, Global Secure Access, workload identities, enterprise apps and app registrations, Defender for Cloud Apps controls, entitlement management, access reviews, PIM and identity monitoring.

The weighting is nearly even across four areas, so there is no domain to skip:

- **User identities (20–25%).** Entra roles (built-in, custom, administrative units, effective permissions), domains, branding and tenant settings, users, groups, custom security attributes, bulk operations in the admin center and PowerShell, device join and registration, licensing. External identities: B2B collaboration settings, invitations, cross-tenant access settings, cross-tenant synchronisation, SAML and WS-Fed identity providers. Hybrid: Entra Connect Sync versus Cloud Sync, password hash sync, pass-through authentication, seamless SSO, AD FS migration, Connect Health.
- **Authentication and access (25–30%).** Authentication methods policy (certificate-based auth, Temporary Access Pass, Authenticator, passkeys/FIDO2), tenant MFA settings, SSPR, Windows Hello for Business, session revocation, password protection, Entra Kerberos. Conditional Access in depth: assignments, grant and session controls, device-based restrictions, continuous access evaluation, authentication context, protected actions, templates and troubleshooting with What If. ID Protection user, sign-in and workload identity risk. Global Secure Access (clients, Private Access, Internet Access, Microsoft 365 traffic profile).
- **Workload identities (20–25%).** Choosing managed identities versus service principals versus user accounts versus managed service accounts; enterprise application settings, Application Proxy, SaaS SSO integration, app roles and assignments, user and admin consent, app collections; app registrations (authentication, API permissions, app roles); Defender for Cloud Apps discovery, connected apps, Conditional Access app control, access and session policies, OAuth app policies.
- **Identity governance (20–25%).** Entitlement management (catalogs, access packages, requests, terms of use, connected organisations, external user lifecycle), access reviews, PIM for Entra roles, Azure resources and groups, approval workflows, emergency access accounts, and monitoring with sign-in, audit and provisioning logs, diagnostic settings, KQL in Log Analytics, workbooks and Identity Secure Score.

Scenarios usually give business requirements with constraints ("contractors must lose access after 90 days unless their sponsor approves") and ask for the feature and its configuration (an access package with an expiry and an access review). Points are lost on:

- **Similar-looking governance features.** PIM (time-bound role activation) versus entitlement management (bundled access for users and guests) versus access reviews (periodic recertification) versus lifecycle workflows.
- **Conditional Access evaluation.** Every matching policy applies and all its grant controls must be met; block wins. Know report-only mode, exclusions for emergency accounts, and which conditions need P2 licensing (risk).
- **Hybrid choices.** When Cloud Sync is enough and when Connect Sync is still required; PHS versus PTA versus federation for resilience and features such as leaked-credential detection.
- **Consent.** User consent settings, admin consent workflow, delegated versus application permissions, and who can grant what.
- **Licensing boundaries.** Which features need Entra ID P1, P2 or Entra ID Governance.

## Study strategy

1. **Foundations.** Revisit SC-900 domain 2 for vocabulary, then read the Entra ID fundamentals docs on tenants, objects, roles and licensing.
2. **Build a tenant.** A Microsoft 365 E5 trial or developer tenant gives you Entra ID P2. Create users and groups (including dynamic groups), administrative units, a custom role and custom security attributes; invite a guest from a second tenant and configure cross-tenant access.
3. **Authentication and Conditional Access.** Enable passkeys and TAP in the authentication methods policy, run SSPR, then build Conditional Access policies from templates in report-only mode, read the sign-in log results, and use What If. Add a risk-based policy and simulate a risky sign-in.
4. **Hybrid.** A small Windows Server VM with AD DS lets you install Cloud Sync and Connect Sync and try PHS and PTA. This is the area most people skip and then lose points on.
5. **Apps.** Register an app, expose an API with app roles, grant consent, publish an on-premises app through Application Proxy, and add a gallery SaaS app with SAML SSO. Connect Defender for Cloud Apps and create a session policy.
6. **Governance last.** Catalogs and access packages, access reviews, PIM for roles and groups, then send logs to Log Analytics and query `SigninLogs` and `AuditLogs` with KQL.

Official resources: the SC-300 self-paced learning paths and instructor-led course on the [certification page](https://learn.microsoft.com/en-us/credentials/certifications/identity-and-access-administrator/), the free practice assessment, the exam sandbox, the SC-300 exam prep videos, and the Microsoft Entra documentation linked from the [study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/sc-300).

How your background helps or misleads:

- **AZ-204 prep** is a real advantage for domain 3: app registrations, MSAL, scopes, delegated versus application permissions, managed identities and the Microsoft identity platform are the developer view of the same objects. The trap is depth: SC-300 asks about tenant-wide consent settings, enterprise application properties and admin workflows that a developer seldom sees.
- **.NET/Angular background**: you have likely wired OIDC and the OAuth authorization code flow with PKCE into SPAs. That helps you reason about tokens and redirect URIs, and continuous access evaluation is easier once you understand token lifetimes.
- **AZ-900** gives you Entra ID versus Azure RBAC, but SC-300 adds Entra roles scoped to administrative units, which is a separate model from Azure RBAC scopes.
- **AWS knowledge**: IAM Identity Center and permission sets are the nearest AWS idea to Entra roles plus access packages, but AWS has no direct equivalent of Conditional Access or ID Protection. Do not map them one to one.

## Differences from related exams

- **SC-300 vs SC-900.** SC-900 describes Entra in one quarter of the exam. SC-300 is entirely Entra, at configuration depth, plus Defender for Cloud Apps and Global Secure Access.
- **SC-300 vs SC-500.** SC-500 includes a slice of Entra (PIM, Conditional Access, MFA, app identity, consent, managed identities) as part of securing Azure workloads, plus Entra Agent ID for AI agents. SC-300 is far deeper on identity, adding hybrid sync, B2B and cross-tenant, governance and monitoring, and skips Azure resource security.
- **SC-300 vs SC-100.** SC-100 designs the identity strategy (agent identities, external identities, privileged access with the enterprise access model, AD DS hardening) and judges whether Conditional Access matches Zero Trust. SC-300 implements those designs. SC-300 is one of the three certifications that qualify you for SC-100.
- **SC-300 vs SCS-C03 (AWS Certified Security – Specialty).** The AWS exam's identity and access management domain covers IAM policies, roles, federation, IAM Identity Center and Organizations SCPs. It is policy-document centric (reading JSON) rather than admin-center configuration. SC-300 has nothing like a policy-evaluation-logic question, while SCS-C03 has nothing like entitlement management or ID Protection.
- **SC-300 vs AZ-104.** AZ-104 starts with users, groups, Azure RBAC and basic tenant settings. SC-300 starts where AZ-104 stops.

## Exam-day notes

- 100 minutes; aim to clear standard questions at 1.5 minutes each, leaving 20–25 minutes for case studies.
- Read requirement words precisely: "minimise administrative effort" usually points to a built-in or automated feature (dynamic groups, access packages, Cloud Sync); "least privilege" points to the narrowest role or an administrative unit scope.
- In Conditional Access questions, check the target (users, guests, workload identities), the cloud apps or actions, the conditions, and only then the controls. Many wrong options pick the right control on the wrong assignment.
- Expect current names: Microsoft Entra ID (not Azure AD), Microsoft Entra Connect, Microsoft Entra Private Access and Internet Access, passkeys (FIDO2).
- If you sit in English before October 28, 2026, or in another language before the localised update (about eight weeks later), expect the April wording: "break-glass accounts", "OAuth 2.0 tokens" in the authentication-methods list, and "Internet Access for Microsoft 365". The features are the same.
