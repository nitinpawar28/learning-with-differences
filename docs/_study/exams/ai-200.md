## Exam format

All facts below are as of 2026-10-24, from the [certification page](https://learn.microsoft.com/en-us/credentials/certifications/azure-ai-cloud-developer-associate/) and the [AI-200 study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-200). Check both again before you book.

- **Exam and credential.** One exam, AI-200: Developing AI Cloud Solutions on Azure, earns Microsoft Certified: Azure AI Cloud Developer Associate. Microsoft lists the level as Intermediate. This is the successor to AZ-204 (Azure Developer Associate), which retired on July 31, 2026.
- **Outline version.** The skills were updated on October 7, 2026. The change log says the only change was a larger share for "Develop AI solutions by using Azure data management services". The skills-at-a-glance list gives that domain 30–35%. The domain heading lower on the same page still says 25–30%, which looks like a leftover from the previous version. This file uses the at-a-glance figure, which matches the change log.
- **Duration.** 120 minutes. Microsoft's [duration page](https://learn.microsoft.com/en-us/credentials/support/exam-duration-exam-experience) uses 120 minutes for role-based exams that may contain labs, so expect a possible lab or interactive component. The certification page says so too.
- **Question types.** Microsoft does not publish the question types for any exam. Its [exam duration and experience](https://learn.microsoft.com/en-us/credentials/support/exam-duration-exam-experience) page shows samples of the formats you may meet: active screen, build list, case studies, drag and drop, hot area, multiple choice and labs, plus problem-and-solution sets. Try them in the [exam sandbox](https://aka.ms/examdemo). The certification page says the exam may have interactive components.
- **Number of questions.** Not published. Microsoft says most exams have 40 to 60.
- **Passing score.** 700 (scaled).
- **Price.** Depends on the country where you test. The page shows it once you choose a location. Taxes and discounts are not included.

## What the exam really tests

AI-200 is a **back-end developer exam for AI workloads**, not an AI model exam. There is no prompt engineering, no Foundry agent building and no model evaluation; those belong to AI-103. The exam asks whether you can build the plumbing that AI apps run on: containers, vector-capable data stores, messaging and serverless glue, secrets and configuration, and observability. The audience profile names Python and vector databases explicitly.

Themes and depth:

- **Containers end to end.** You build images in Azure Container Registry (including ACR Tasks, which build in the cloud with no local Docker), deploy them to App Service with environment variables and secrets, run them in Container Apps (revisions, traffic splitting, KEDA scale rules on queue length or HTTP) and deploy to AKS with YAML manifests. Troubleshooting is tested: reading logs and events, and finding why a pod or revision cannot reach a dependency.
- **Data services for AI, the largest domain.** The exam goes deep on three stores:
    - **Cosmos DB for NoSQL:** SDK queries, Request Unit costs, indexing policies, consistency levels, vector embeddings with vector search, and the change feed processor.
    - **Azure Database for PostgreSQL:** schema and data types, indexes, pgvector index choices and their compute cost, sizing compute and memory for vectors, RAG with metadata filters, and connection pooling.
    - **Azure Managed Redis:** cache-aside, TTL and invalidation, and vector indexes.

    Expect "which store or index for this retrieval need" and "why is this query expensive" scenarios.
- **Messaging and Functions.** For Service Bus you need queues compared with topics and subscriptions, dead-lettering, sessions and locks at a working level. For Event Grid you need custom topics, filters and retry or dead-letter behaviour. For Functions you need triggers and bindings and deployment configuration.
- **Security and observability.** Key Vault secret retrieval and rotation (with managed identity), App Configuration (including Key Vault references and feature flags), OpenTelemetry tracing across services, and writing KQL against logs and metrics.

Where candidates lose points:

- They apply AZ-204 habits to Cosmos DB without thinking about vectors. The exam wants embedding storage, vector index policy and similarity queries, not just CRUD.
- They choose the wrong messaging service. Service Bus is for commands and work that must not be lost, with ordering and dead-lettering. Event Grid is for reactive notification of discrete events.
- They mix up revision modes and scaling triggers in Container Apps, or forget that KEDA scales on event sources rather than CPU.
- They lose time on KQL syntax: `summarize`, `bin()`, `where`, `project`, `join`, `render`.
- They miss the Python angle. Code fragments are likely to be Python SDK calls.

## Study strategy

1. **Foundations first.** Revisit identity (managed identities, `DefaultAzureCredential`, RBAC on data planes), networking basics and resource organisation. AZ-900 gives you the vocabulary; your AZ-204 prep gives you most of the identity patterns.
2. **Containers.** Your CKAD preparation is the biggest asset here. Pods, Deployments, Services, ConfigMaps, Secrets, probes and `kubectl logs`/`describe`/`get events` map straight onto the AKS bullets. Add the Azure-specific parts: ACR authentication from AKS (attach ACR or a managed identity), ACR Tasks, Container Apps environments and revisions, KEDA scalers in Container Apps, and App Service for containers.
3. **Data for AI, with the most hands-on time.** Build one small RAG back end three ways. Store embeddings in Cosmos DB with a vector index and query it with vector distance. Repeat in PostgreSQL with pgvector (try both HNSW and IVFFlat and compare). Add Azure Managed Redis as a cache and as a vector index. Measure RU charges and query plans. The AI part only needs an embeddings endpoint. The exam does not test model choice.
4. **Messaging and Functions.** Wire a Function triggered by Service Bus that writes to Cosmos DB, and an Event Grid subscription with a filter and dead-letter destination.
5. **Security and monitoring.** Move every secret into Key Vault and App Configuration, instrument the app with the Azure Monitor OpenTelemetry distro, then write KQL queries for failures, latency percentiles and dependency calls.
6. **Official resources.** The certification page links the self-paced learning paths ("Prepare for the exam"), the [study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-200), the [exam sandbox](https://aka.ms/examdemo) and the AI Skills Navigator practice assessment.

How your background helps or misleads:

- **AZ-204 prep** carries over for Container Registry, Container Apps, Functions, Service Bus, Event Grid, Cosmos DB SDK and change feed, Key Vault and App Configuration. It misleads where AZ-204 topics were dropped: API Management, Event Hubs, Queue Storage, Blob Storage operations, Microsoft Graph and MSAL flows are not in this outline. Don't spend time there.
- **.NET background.** The concepts transfer (the SDKs are parallel), but practise in Python, because the audience profile names it.
- **Angular.** Not used; this is a back-end exam.

## Differences from related exams

- **AI-200 vs AZ-204 (predecessor).** AZ-204 was a general Azure developer exam built around App Service, Functions, storage, identity platform, API Management and Event Hubs. AI-200 keeps the developer role but points it at AI back ends. It adds AKS, KEDA, PostgreSQL with pgvector, Azure Managed Redis, vector search and OpenTelemetry with KQL, and drops the identity-platform, Graph and API gateway material.
- **AI-200 vs AI-103.** These are the two halves of an AI app. AI-103 builds the intelligent part in Microsoft Foundry: models, agents, RAG pipelines in Azure AI Search, evaluation and safety. AI-200 builds the services around it: containers, databases, messaging and telemetry. AI-200 has no Foundry objectives at all.
- **AI-200 vs DVA-C03 (AWS Certified Developer – Associate).** These are the same tier and the same broad role: an SDK-centred developer who writes against managed services. The AWS developer exam is serverless-first. DVA-C02 centres on Lambda, API Gateway, DynamoDB, SQS, SNS, EventBridge and Step Functions, with whole domains on security and on deployment and CI/CD. AI-200 is container-first (ACR, Container Apps, AKS), spreads data across three stores with explicit vector search, and has no CI/CD domain. Roughly, Service Bus and Event Grid map to SQS/SNS and EventBridge, Functions to Lambda, Cosmos DB to DynamoDB, and Key Vault and App Configuration to Secrets Manager and AppConfig or Parameter Store. As of 2026-10-24 the [AWS Developer – Associate page](https://aws.amazon.com/certification/certified-developer-associate/) says registration for DVA-C03 opens on October 27, 2026 and the last day for DVA-C02 is November 30, 2026. The comparison above is based on the DVA-C02 role and services, because the DVA-C03 exam guide is not yet published. Check it for the final domain list.
- **AI-200 vs DP-420.** DP-420 covers Cosmos DB alone, much more deeply: partitioning, hierarchical partition keys, all change feed modes, Fleet management, Fabric mirroring and agent memory stores. AI-200 touches Cosmos DB as one of three data stores.
- **AI-200 vs CKAD.** CKAD is a hands-on terminal exam on Kubernetes alone. AI-200 asks about AKS manifests and troubleshooting in multiple-choice form, next to managed alternatives such as Container Apps.

## Exam-day notes

- You have 120 minutes. If a lab or case study appears, budget its time when you see the item count at the start. Don't let one Kusto or YAML question take ten minutes.
- Microsoft Learn is open in a split pane, but searching it is slow. Use it only to check an exact parameter or KQL function, never to learn a topic.
- Read the constraint words: "minimise cost", "least administrative effort", "without code changes" and "must not lose messages". They decide between Container Apps and AKS, Service Bus and Event Grid, and caching and re-querying.
- Problem-and-solution sets ("does this solution meet the goal?") repeat one scenario with different proposed solutions. Judge each solution on its own, and note that you cannot take a break in the middle of a set.
- Watch for answers that use connection strings or keys where a managed identity is possible. The outline favours keyless patterns.
