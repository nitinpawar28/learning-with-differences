## Exam format

All facts below are as of 2026-10-24. Confirm them on the official pages before booking anything.

- **Duration.** The [certification page](https://learn.microsoft.com/en-us/credentials/certifications/azure-administrator/) gives 100 minutes. Microsoft's [exam duration and experience page](https://learn.microsoft.com/en-us/credentials/support/exam-duration-exam-experience) lists 100 minutes of exam time (120 minutes of seat time) for role-based exams without labs, and 120 minutes (140 seat) for exams that may contain labs. Microsoft does not say which exams have labs. Your booking shows the time you actually get.
- **Questions.** Microsoft does not publish the count or the question types for a given exam. The duration page says most Microsoft exams have 40 to 60 questions. It also demonstrates the types you may meet: active screen, build list, case studies, drag and drop, hot area, multiple choice and labs, plus the problem-and-solution sets ("does this solution meet the goal"). Use the exam sandbox, linked from the certification page, to try the interface.
- **Passing score.** 700 on a scale of 1 to 1000, scaled rather than a percentage ([exam scoring and score reports](https://learn.microsoft.com/en-us/credentials/certifications/exam-scoring-reports)).
- **Price.** The certification page says only that the price depends on the country or region where the exam is proctored. The scheduling flow shows your local price.
- **Languages.** English, Chinese (Simplified), Korean, Japanese, French, Spanish, German, Portuguese (Brazil), Chinese (Traditional) and Italian. Microsoft updates the English version first. Localised versions follow about eight weeks later. If your language isn't offered, you can request an extra 30 minutes.
- **Delivery.** Proctored through Pearson VUE, at a test centre or online. Role-based exams let you open Microsoft Learn in a split pane during the exam. It is meant for the occasional lookup, and the exam is timed so that you can't look everything up.
- **Retakes.** You can retake 24 hours after the first attempt. Later retakes need longer waits.
- **Renewal.** The certification page gives a renewal frequency of 12 months. Renewal is a free, unproctored, open-book online assessment on Microsoft Learn, which you can take during a six-month eligibility window before the certification expires ([certification renewal](https://learn.microsoft.com/en-us/credentials/certifications/renew-your-microsoft-certification)).
- **Current outline.** Skills measured as of April 17, 2026. The [study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/az-104) change log marks the audience profile and these groups as minor changes: *Configure Azure Files and Azure Blob Storage*, *Create and configure virtual machines*, *Provision and manage containers in the Azure portal*, *Configure and manage virtual networks in Azure* and *Monitor resources in Azure*. Objective 3.2.7 is transcribed exactly as the study guide prints it ("Deploy and configure an Azure Virtual Machine Scale Sets").

## What the exam really tests

AZ-104 is an operator's exam. The verbs are *create*, *configure*, *manage*, *interpret* and *troubleshoot*. The questions put you in a running subscription with a problem and ask which setting, command or sequence of steps fixes it.

- **Identity and governance (20–25%).** Microsoft Entra users, groups, licences, external users and self-service password reset. Azure RBAC built-in roles at management group, subscription, resource group and resource scope, and reading an access assignment to say what someone can actually do. Azure Policy (definitions, initiatives, assignments and effects), resource locks (CanNotDelete versus ReadOnly), tags, moving resources, and budgets with Advisor cost recommendations. A classic trap is mixing up an Entra role (directory permissions) with an Azure RBAC role (resource permissions).
- **Storage (15–20%).** Storage firewalls and virtual network rules, SAS tokens (account, service and user delegation) and stored access policies, access key rotation, and identity-based access to Azure Files. Then redundancy, object replication, encryption, AzCopy and Storage Explorer, Azure Files shares, snapshots and soft delete, blob tiers, lifecycle management and versioning. Expect questions that ask which feature combination meets a retention or recovery requirement at the lowest cost.
- **Compute (20–25%).** Reading and editing ARM templates and Bicep files, deploying them, exporting a deployment, and converting ARM JSON to Bicep. VMs: sizes, disks, encryption at host, moving between resource groups, subscriptions and regions, availability zones versus availability sets, and Virtual Machine Scale Sets. Containers: Azure Container Registry, Azure Container Instances and Azure Container Apps, and how each one sizes and scales. App Service: plans and scaling, TLS certificates, custom domains, backup, networking and deployment slots.
- **Networking (15–20%).** VNets, subnets, peering (it is not transitive), public IPs, user-defined routes, NSGs and application security groups, effective security rules, Azure Bastion, service endpoints versus private endpoints, Azure DNS, and public and internal load balancers, with troubleshooting for both connectivity and load balancing.
- **Monitor and maintain (10–15%).** Metrics versus logs in Azure Monitor, diagnostic settings, KQL queries in Log Analytics, alert rules, action groups and alert processing rules, Azure Monitor Insights for VMs, storage and networks, Network Watcher and Connection Monitor. Recovery Services vaults versus Backup vaults (which workloads go where), backup policies, restores, Azure Site Recovery failover, and backup reports and alerts.

Where candidates lose points: which vault type a workload needs, the order of steps (for example, a DNS record before the custom domain binding, or removing a lock before a move), what a ReadOnly lock blocks (it can stop operations you wouldn't expect, such as listing storage keys), the effective NSG result when subnet and NIC rules both apply, and whether a resource can be moved at all.

## Study strategy

1. **Foundations first.** Begin with identity and governance. Every later task depends on understanding scope (management group, subscription, resource group, resource) and on the difference between Entra roles and Azure RBAC. You know the vocabulary from AZ-900. Now practise reading role assignments and policy effects.
2. **Networking next, early and hands-on.** It is the domain most people find hardest, and storage private endpoints, App Service networking and Bastion all depend on it. Build two peered VNets with a UDR, an NSG and a load balancer, break them, then use Network Watcher (IP flow verify, next hop, connection troubleshoot) to find out why.
3. **Storage and compute.** Make a storage account with each kind of SAS, set lifecycle rules, and test soft delete and versioning. Deploy one VM from Bicep, then change and redeploy it. Run the same container on Container Instances and on Container Apps to see how scaling differs. Use deployment slots on App Service.
4. **Monitor and back up last.** Write a few KQL queries, create an alert with an action group, back up a VM and a file share, and run a Site Recovery test failover.

Official resources: the [AZ-104T00 instructor-led course](https://learn.microsoft.com/en-us/training/courses/az-104t00) and its matching self-paced paths, starting with [Prerequisites for Azure administrators](https://learn.microsoft.com/en-us/training/paths/az-104-administrator-prerequisites/). Also use the free practice assessment and the *Exam AZ-104 prep videos* (Exam Readiness Zone), both linked from the certification page, and the study guide's documentation links (Microsoft Entra ID, Azure Policy, Azure Storage, ARM templates, Azure Container Instances, Azure Container Apps, App Service, Azure DNS, Azure Bastion, Application Gateway, Azure Monitor, Network Watcher, Azure Site Recovery, Azure Backup). An Azure free account or a pay-as-you-go subscription with a budget alert is enough for every lab here.

How your background helps or misleads:

- **AZ-900** gives you the map, but every bullet here asks you to *do* something, so recognising names won't be enough.
- **AZ-204 preparation** helps a lot with App Service, deployment slots, Container Registry, Container Apps and managed identities. Be careful: AZ-104 asks about these from the platform side (plans, scaling, networking, backup, TLS bindings), not the SDK side, and it rarely cares about code.
- **CKAD preparation** helps with containers and YAML, but AKS is not in this outline. The container bullets are Container Registry, Container Instances and Container Apps, so don't spend time on kubectl here.
- **.NET background.** PowerShell will feel natural. Practise the Azure CLI as well, because answer options mix `az` and `Az` cmdlets.
- **AWS knowledge.** Resource groups have no direct AWS equivalent. NSGs are stateful like security groups, but they attach to subnets *or* NICs and have priorities. Peering is non-transitive on both clouds.

## Differences from related exams

- **AZ-104 vs SAA-C03 (AWS Certified Solutions Architect – Associate).** Same level, different stance. SAA-C03 is a *design* exam. It asks which architecture is most resilient, performant, secure or cost-effective. AZ-104 is an *operate* exam. It asks how to configure, interpret and fix things. SAA-C03 has no hands-on configuration detail (no template editing, no exact setting names). AZ-104 has less architecture trade-off reasoning and more step-by-step precision. Topic overlap is high: identity, VPC/VNet design, storage classes and tiers, load balancing, backup and DR.
- **AZ-104 vs AZ-305.** AZ-305 takes the same services and asks *which one to recommend, and why*. It expects you to already know how they are configured. AZ-104 is the required prerequisite for the Solutions Architect Expert certification.
- **AZ-104 vs AZ-700.** AZ-104 networking covers VNets, peering, UDRs, NSGs, Bastion, endpoints, DNS and load balancers. AZ-700 adds hybrid connectivity (VPN, ExpressRoute, Virtual WAN), Application Gateway, Front Door, Traffic Manager, Azure Firewall and WAF, DNS Private Resolver, Route Server and Virtual Network Manager, at engineering depth.
- **AZ-104 vs AZ-500.** AZ-500 goes deep on security controls (Defender for Cloud, Key Vault, Entra privileged access). AZ-104 touches them only where an administrator configures them.

## Exam-day notes

- Budget about a minute and a half per question, and leave time for any case study, which comes as a separate section with its own review rules.
- In "does this solution meet the goal" sets you can't go back once you answer, and each set has several candidate solutions. Judge each one on its own.
- Use Microsoft Learn access sparingly, for an exact SKU limit or a setting name, never to read a whole article.
- Watch for qualifiers: *minimise administrative effort* favours Policy or a built-in feature over scripts. *Least privilege* points to the narrowest built-in role at the narrowest scope.
- Breaks: five minutes are built into the exam time, but once you take a break you can't return to questions you saw before it.
