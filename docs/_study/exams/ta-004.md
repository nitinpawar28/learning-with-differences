## What the exam really tests

The exam tests foundational, practical Terraform knowledge: can you write and run a configuration, understand what Terraform will do and why, and manage state safely. It also checks whether you know what HCP Terraform adds over the Community Edition CLI.

- **IaC concepts.** Declarative versus imperative tooling, idempotence, version control and review of infrastructure changes, and Terraform's provider model that lets one workflow cover many clouds and SaaS services.
- **Providers and state.** The `required_providers` block, version constraints (`~>`, `>=`), the dependency lock file `.terraform.lock.hcl`, provider aliases for multiple regions or accounts, and what state is for (mapping configuration to real objects, tracking metadata and performance).
- **The core workflow.** `init`, `validate`, `plan`, `apply`, `destroy` and `fmt`, what each one reads and changes, and what `-out` plan files, `-replace` and `-refresh-only` do.
- **Configuration language.** `resource` versus `data` blocks; references such as `aws_instance.web.id`; variables with types, defaults, validation and `sensitive`; outputs; lists, maps, objects, sets and tuples; `count`, `for_each`, `for` expressions, `dynamic` blocks and built-in functions; implicit dependencies versus `depends_on`, and the `create_before_destroy` lifecycle rule; custom conditions (variable `validation`, `precondition`, `postcondition`, `check` blocks); and secrets handling, including the fact that `sensitive` values still land in state, how ephemeral values and write-only arguments keep secrets out of state and plan files, and how Vault fits.
- **Modules.** Sources (local paths, the public and private registries, Git), passing inputs and reading outputs, why a child module cannot see the caller's variables, and pinning module versions.
- **State management.** The local backend, state locking, remote backends configured with a `backend` block, and dealing with drift (`plan -refresh-only`, `terraform state` subcommands, `moved` and `removed` blocks).
- **Maintenance.** `import` blocks and `terraform import`, `terraform state list` and `show`, and `TF_LOG` and `TF_LOG_PATH` for verbose logging.
- **HCP Terraform.** Remote runs, workspaces and projects, VCS-driven and CLI-driven workflows, variable sets, teams and permissions, policy enforcement, run tasks, the private registry, and the `cloud` block that connects a configuration to HCP Terraform.

The [Exam Content List](https://developer.hashicorp.com/terraform/tutorials/certification-004/associate-review-004) names four topics that are new compared with version 003: `depends_on` and `create_before_destroy` lifecycle rules (4f), custom conditions (4g), ephemeral values and write-only arguments (4h), and organizing HCP Terraform workspaces and projects (8c). Older practice material will not cover them.

Where candidates lose points: commands that sound alike (`terraform refresh` versus `plan -refresh-only`, `state rm` versus `destroy`); version constraint operators; which files belong in version control (the lock file does, state files and `.terraform/` do not); and HCP Terraform features that are not in the open-source CLI.

## Study strategy

1. **Foundations first.** The IaC idea and the core workflow. Install Terraform 1.12 and work through the official *Get Started* tutorials for one cloud (Azure or AWS suits this reader).
2. **Write real configurations.** Build a small network and a VM or container app with variables, outputs, `for_each` and a module. Change something by hand in the portal and watch `plan` detect the drift. Import a resource you created by hand.
3. **Move state to a remote backend.** Use an Azure Storage account or an S3 bucket, or HCP Terraform's free tier, and see locking in action by running two applies at once.
4. **Try HCP Terraform.** Create a project and workspace, connect a VCS repository, set a variable set, and run a plan remotely.
5. **Use the official study path.** The [004 exam preparation tutorials](https://developer.hashicorp.com/terraform/tutorials/certification-004) contain a learning path, an exam content list that maps each objective to tutorials and documentation and lists the content differences from 003, and sample questions.

How your background helps or misleads:

- **AZ-900 and Azure experience** help you read `azurerm` resources. If you have used Bicep or ARM templates, the declarative model is familiar. The difference that matters is state: ARM tracks deployments in Azure itself, while Terraform keeps its own state file, which you must store, lock and protect.
- **Basic AWS** knowledge makes the many `aws_*` examples in HashiCorp's material easy to follow. CloudFormation, like ARM, has no separate state file to manage.
- **CKAD and Kubernetes** experience gives you the declarative "desired state" mindset, but Terraform does not reconcile continuously. It only changes things when you run `apply`.
- **.NET** experience helps with types and modules as a reuse idea. HCL is not a general-purpose language, so loops and conditions work through `count`, `for_each` and expressions, not statements.

## Differences from related exams

- **TA-004 vs TA-003.** Same format and length. 004 tests Terraform 1.12, adds the four new objectives listed above, and reflects the renaming of Terraform Cloud to HCP Terraform, with projects alongside workspaces.
- **TA-004 vs the Terraform Authoring and Operations Advanced and Infrastructure Engineer Professional exams.** Those are the higher-level Terraform certifications, and passing one renews the Associate. The Associate is a one-hour multiple-choice exam that tests foundational recognition and understanding.
- **TA-004 vs AZ-400 (Azure DevOps Engineer Expert).** AZ-400 covers the whole delivery pipeline (source control, CI/CD, security, monitoring) on Azure DevOps and GitHub, where infrastructure as code (Bicep, ARM, Terraform) is one topic. TA-004 goes deep on that one topic.
- **TA-004 vs DOP-C02 (AWS DevOps Engineer – Professional).** The AWS exam expects CloudFormation and the AWS CDK for infrastructure as code within a much broader DevOps scope. TA-004 is tool-specific and vendor-neutral.
- **TA-004 vs AZ-104 and SAA-C03.** Those test what to build on a cloud. TA-004 tests how to describe and manage it as code, whatever the cloud.

## Exam-day notes

- **Time:** 1 hour is enough for most candidates. Flag the uncertain questions and review them at the end.
- **Read every word of command questions.** One flag changes the answer (`-refresh-only`, `-replace`, `-auto-approve`, `-target`).
- **Remember what is HCP-only.** Remote runs, Sentinel or OPA policy enforcement, run tasks, the private registry and team permissions belong to HCP Terraform or Terraform Enterprise, not the CLI.
- **Traps:** `terraform validate` does not contact providers' APIs; `terraform fmt` changes only layout; `sensitive = true` hides values in output but not in state; `count` and `for_each` cannot be used together on one resource; removing a resource from configuration plans its destruction unless you use a `removed` block or `state rm`.
