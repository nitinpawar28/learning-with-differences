## Exam format

All facts below are as of 2026-10-24, taken from the [GitHub Actions certification page](https://learn.microsoft.com/en-us/credentials/certifications/github-actions/) and the [GH-200 study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/gh-200). Confirm them on those pages before you book, because GitHub exams moved onto Microsoft Learn recently and the details are still settling.

- **Delivery.** A proctored exam scheduled through Pearson VUE from the Microsoft Learn certification page. Microsoft recommends registering with a personal Microsoft account, not a work or school account, because exam records tied to an organisational account are lost if you leave that organisation.
- **Duration.** 100 minutes.
- **Question types and count.** Microsoft does not publish a question count. The page warns that the exam "may have interactive components". Expect mostly multiple-choice and multiple-select items built around YAML snippets, log excerpts and settings screens. The [exam sandbox](https://GHCertDemo.starttest.com) shows the question interface.
- **Passing score.** 700 on a scale of 1–1000 (study guide, citing [exam scoring and score reports](https://learn.microsoft.com/en-us/credentials/certifications/exam-scoring-reports)).
- **Price.** Not printed on the page. It says the price depends on the country or region where the exam is proctored, and you see the price when you schedule.
- **Languages.** English, Spanish, Portuguese (Brazil), Korean, Japanese. Localised versions lag English updates by about eight weeks. If your language is not offered you can request 30 extra minutes.
- **Retakes.** You can retake 24 hours after a first failed attempt. Later retakes follow the [retake policy](https://learn.microsoft.com/en-us/credentials/support/retake-policy).
- **Validity and renewal.** The certification page says GitHub certifications are valid for **2 years**, and that GitHub is moving to Microsoft's recertification process. Certifications that expire before that process is available are extended by 6 months, and if yours has already expired the page says to contact learn@github.com for one exam voucher for your first renewal attempt. The study guide's generic table still says associate-level Microsoft certifications expire annually. Treat the certification page as authoritative and check again near your expiry date.
- **Practice.** The certification page links a Microsoft Learn practice assessment.

## What the exam really tests

The outline (skills measured as of January 2026, a significant rewrite) is about **operating Actions as a platform**, not just writing one CI file. Two of the five domains (Author and manage workflows; Manage GitHub Actions for the enterprise) are each worth 20–25%. Security and optimisation is the smallest domain, but security ideas also run through every other domain.

The themes:

- **Workflow syntax at reading depth.** You must predict what a YAML file does: which events fire it, which jobs run in which order (`needs`), what a `matrix` with `include`/`exclude` expands to, what `if:` conditions evaluate to, which context (`github`, `env`, `vars`, `secrets`, `inputs`, `matrix`, `needs`, `steps`) holds a value, and when an expression is evaluated. The January 2026 outline names YAML anchors and aliases, service containers, `GITHUB_STEP_SUMMARY` and runner image changes (Ubuntu 20.04 deprecation and the `windows-latest` move to Windows Server 2025).
- **Moving data.** Outputs, `GITHUB_OUTPUT` and `GITHUB_ENV`, artifacts compared with caches, reusable-workflow outputs, and retention settings managed through the REST API.
- **Reuse models.** The outline explicitly asks you to tell apart starter workflows (a copied scaffold that becomes independent), reusable workflows (one central definition called with `workflow_call`) and composite actions (packaged steps). This is a favourite source of "which should you use" scenarios.
- **Authoring actions.** JavaScript compared with Docker compared with composite actions, `action.yml` metadata, workflow commands inside actions, Marketplace publishing, and versioning with tags and releases. Immutable actions and version pinning are named explicitly in the outline.
- **Enterprise governance.** Allowed-actions policies, runner groups, self-hosted compared with GitHub-hosted runners, IP allow lists and networking, and secrets and variables scoped to organisation, repository or environment.
- **Security.** Script injection from untrusted `github.event` data, least-privilege `permissions:` for `GITHUB_TOKEN` compared with a PAT, OIDC federation to clouds (the `id-token: write` permission), pinning to full commit SHAs, environment protection rules and required reviewers, and artifact attestations for provenance (SLSA).

Candidates lose points on: the difference between a cache and an artifact; which secret scope wins and whether secrets reach reusable workflows (they must be passed or inherited); what `GITHUB_TOKEN` can and cannot trigger; where `env:` is visible at workflow, job and step level; and enterprise policy questions that people who have only used personal repositories have never seen.

## Study strategy

1. **Foundations first.** Read the workflow syntax reference and the contexts and expressions reference on [GitHub Docs](https://docs.github.com/actions) end to end once. Most wrong answers come from not knowing exactly what a keyword does.
2. **Build, do not just read.** In a free personal repository, build a workflow with a matrix (with include and exclude), a service container (PostgreSQL or Redis), job outputs, an artifact upload and download, a cache, a job summary, and a manual `workflow_dispatch` with typed inputs. Then split part of it into a reusable workflow and a composite action. Write one small JavaScript action and one Docker action with their own `action.yml`.
3. **Security hands-on.** Set `permissions:` at workflow and job level, deliberately write an injectable `run:` step and then fix it with an intermediate environment variable, pin an action to a SHA, and set up OIDC from a workflow to an Azure subscription (federated credential on an Entra app registration) or an AWS role.
4. **Enterprise topics.** You probably have no enterprise account, so study these from the docs and the Microsoft Learn module [Manage GitHub Actions for the enterprise](https://learn.microsoft.com/en-us/training/modules/manage-github-actions-enterprise/). Register a self-hosted runner on your own machine or in a container to see runner labels and groups in practice.
5. **Official training.** The Microsoft Learn learning path [Automate your workflow with GitHub Actions](https://learn.microsoft.com/en-us/training/paths/github-actions/), the docs page on [releasing and maintaining actions](https://docs.github.com/actions/sharing-automations/creating-actions/releasing-and-maintaining-actions), and the practice assessment on the certification page.

How your background helps or misleads:

- **AZ-204 and AZ-900.** OIDC federation to Azure is easy for you if you understand managed identities and federated credentials. Do not over-study Azure deployment details: the exam cares about the GitHub side (the `azure/login` action, the `id-token` permission, the subject claim), not App Service settings.
- **CKAD prep.** Containers help with Docker actions, service containers and the `container:` job option. Do not confuse Actions service containers with Kubernetes sidecars: they are separate containers on the same Docker network, addressed by label name (or by `localhost` when the job runs directly on the runner).
- **.NET and Angular.** You know `setup-dotnet`, `setup-node` and caching NuGet and npm packages. Be careful: if you know Azure Pipelines YAML, its stages, templates and variable groups look similar to Actions concepts but use different keywords and rules.

## Differences from related exams

- **GH-200 vs AZ-400 (Designing and Implementing Microsoft DevOps Solutions).** AZ-400 is an expert-level Microsoft exam about the whole DevOps practice: process, source control strategy, pipelines in both Azure Pipelines and GitHub Actions, security and compliance, and instrumentation. GitHub Actions is one tool among several there, and questions are about design choices. GH-200 is narrower and deeper: it expects you to know exact YAML keywords, context names, environment files and enterprise runner settings that AZ-400 only touches.
- **GH-200 vs DOP-C02 (AWS Certified DevOps Engineer – Professional).** DOP-C02 tests CI/CD with AWS-native services (CodePipeline, CodeBuild, CodeDeploy), infrastructure as code, monitoring, incident response and resilience, in long multi-service scenarios. GH-200 is tool-specific and vendor-neutral about the cloud target; the only cloud link is OIDC federation. The shared concepts are pipelines, artifacts, approvals, short-lived credentials and supply-chain integrity.
- **GH-200 vs GH-900.** GH-900 introduces Actions in a few bullets. GH-200 expects you to have written and debugged real workflows.
- **GH-200 vs GH-500.** GH-500 uses Actions as the engine for CodeQL code scanning and dependency review. GH-200 covers how the engine itself is secured (token permissions, injection, pinning, attestations).
- **GH-200 vs GH-600.** GH-600 asks you to run AI agents in CI and to set up a Copilot agent's environment. GH-200 is the workflow knowledge underneath that.

## Exam-day notes

- 100 minutes is enough if you do not spend too long on YAML exhibits. On a long snippet, read the question first, then look only at the keys it asks about (`on:`, `needs:`, `if:`, `permissions:`).
- Matrix questions: count combinations carefully. `exclude` is applied first, then `include` adds or extends entries. An `include` entry that matches no existing combination becomes a new job.
- Watch the wording "least privilege", "without storing long-lived credentials" and "centrally maintained". These usually point to job-level `permissions:`, OIDC, and reusable workflows respectively.
- Choose between disabling and deleting a workflow carefully: disabling keeps the file and its run history, and the workflow can be enabled again.
- Some items may be about preview features, because the study guide says commonly used previews can appear. Do not dismiss an option just because it sounds new.
- Do not leave questions blank. Microsoft's [exam scoring page](https://learn.microsoft.com/en-us/credentials/certifications/exam-scoring-reports) says there is no penalty for guessing: an incorrect answer simply earns no point.
