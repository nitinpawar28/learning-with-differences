## What the exam really tests

The audience profile describes an engineer who *operates, integrates, supervises and governs* AI agents in production SDLC workflows, "using GitHub as the system of record and control plane". So this is not a model-building or prompt-writing exam. It tests whether you can run coding agents (GitHub Copilot's cloud agent, custom agents, agents invoked in CI) safely and observably.

Themes and depth:

- **Architecture and SDLC fit (15–20%).** Choosing which SDLC steps an agent should do, defining inputs, outputs and success criteria, recognising anti-patterns, separating planning from execution, asking for a structured plan, validating it, and blocking action until the plan is approved. Deciding the level of autonomy and where a human steps in without slowing delivery.
- **Tools and environment (20–25%, the largest domain).** Choosing and configuring tools and tool permissions; MCP servers, including the GitHub remote MCP server, MCP registries and allow lists; scoping an agent to a repository or branch; invoking an agent from a CI workflow; letting it create branches and pull requests; and error handling with retries, rollbacks, escalation and traceability.
- **Memory and state (10–15%).** Short-term, long-term and external memory, scoping and pruning, saving progress as durable artifacts (plans, notes, pull request descriptions), resuming without repeating work, and detecting drift, stale context and conflicting context.
- **Evaluation and tuning (15–20%).** Defining expected outcomes, qualitative and quantitative signals (including results of automated scanners such as code scanning), classifying failures as reasoning errors, tool misuse or context and environment problems, and then tuning instructions, memory and tool access.
- **Multi-agent orchestration (15–20%).** Orchestration patterns, isolating agents that run in parallel, resolving overlapping changes, duplicated effort and contradictory outputs, audit-ready artifacts, recovering from partial or stalled runs, and adding, replacing or retiring agents without breaking running workflows.
- **Guardrails (10–15%).** Classifying actions by operational, security and compliance risk, assigning autonomy levels, least-privilege permissions, explicit approval for irreversible changes, and, importantly, *not* adding approvals that do not reduce risk.

Where candidates lose points: choosing "add a human approval to everything" when the outline rewards approvals in proportion to risk; confusing tool permissions with repository permissions; and not knowing GitHub-specific controls (branch protection and rulesets on agent branches, Copilot setup steps, MCP allow lists, Actions logs as audit evidence). Because the exam is new and agent features change quickly, the study guide's warning that commonly used preview features can appear matters more here than on other exams.

## Study strategy

1. **Foundations first: take or at least study GH-300.** GH-600 assumes you already know Copilot agent mode, the cloud agent, custom instructions, custom agents and MCP. GH-200 knowledge (workflows, permissions, environments) is the second foundation, because agents running in CI are Actions jobs with the same security model.
2. **Official modules.** The study guide lists three Microsoft Learn modules: [Foundations of Agentic AI in GitHub](https://learn.microsoft.com/en-us/training/modules/foundations-agentic-ai/), [Designing Agent Architecture and SDLC Integration](https://learn.microsoft.com/en-us/training/modules/design-agent-architecture-integration/) and [Tooling, MCP, and Agent Execution Environments](https://learn.microsoft.com/en-us/training/modules/agent-tooling-mcp-execution-environments/). For the later domains it points to GitHub Docs pages: [preparing for custom agents](https://docs.github.com/copilot/how-tos/administer-copilot/manage-for-organization/prepare-for-custom-agents), [custom agents with the Copilot SDK](https://docs.github.com/copilot/how-tos/copilot-sdk/use-copilot-sdk/custom-agents), [Copilot memory](https://docs.github.com/copilot/concepts/agents/copilot-memory), the [implementation planner tutorial](https://docs.github.com/copilot/tutorials/customization-library/custom-agents/implementation-planner) and the [cloud agent risks and mitigations](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/risks-and-mitigations) page. (The study guide's guardrails link joins two URLs into one by mistake; the second is the one linked here.)
3. **Hands-on.** In a test repository: assign an issue to the Copilot cloud agent and watch it plan, branch and open a pull request; write a custom agent profile with limited tools; add the GitHub MCP server and an MCP allow list; create a Copilot setup steps workflow to prepare the agent's environment; protect the agent's branches with a ruleset; run an agent from a workflow; and look at the session logs to find out why a run failed. Then run two agents on separate issues and handle a conflict between their pull requests.
4. **Evaluation habit.** For every agent task, write the success criteria first (tests passing, code scanning clean, scope limited to certain paths) and check the pull request against them. That is the evaluation domain in practice.

How your background helps or misleads: CKAD prep helps with isolation and least privilege (an agent sandbox is similar to a pod with a restricted service account), and AZ-204 prep helps with managed identities and secrets for tools. Your .NET and Angular work gives you real repositories to practise on. The risk is your general agentic-AI reading: frameworks such as Semantic Kernel or LangGraph use their own words for memory and orchestration. This exam uses GitHub's controls and vocabulary, so map general ideas onto Copilot, MCP, Actions and repository rules.

## Differences from related exams

- **GH-600 vs GH-300.** GH-300 is about using and administering Copilot as a product. GH-600 is about running agents as part of the delivery system: planning compared with execution, autonomy levels, memory, evaluation, multi-agent coordination and recovery.
- **GH-600 vs AIP-C01 (AWS Certified Generative AI Developer – Professional).** AIP-C01 is about building generative AI applications on AWS (Amazon Bedrock, knowledge bases and retrieval, agents, guardrails, model evaluation, cost and operations). GH-600 does not ask you to build an AI application. It asks you to supervise coding agents that change your codebase. They share ideas about guardrails, evaluation and agent tools, but each is tied to a different platform.
- **GH-600 vs NCP-AAI (NVIDIA Agentic AI).** NCP-AAI covers agent architectures, frameworks, deployment and scaling on NVIDIA's stack. It is more about building agents, while GH-600 is about running them in the SDLC.
- **GH-600 vs AI-103 and AI-300 (Microsoft).** The Microsoft AI exams build agents and AI solutions on Azure (Microsoft Foundry). GH-600 is the developer-workflow side: the agents act on your repositories, and GitHub is the control plane.
- **GH-600 vs CLAUDE-ARCH-F and CLAUDE-ARCH-P.** The Anthropic architecture credentials focus on designing solutions with Claude models and agent tooling. GH-600 is tied to GitHub's agent surfaces and governance.

## Exam-day notes

- 120 minutes is more generous than the other GitHub exams. Use it to read the scenario twice: most questions turn on one constraint (irreversible, compliance-sensitive, parallel, long-running).
- Guardrail questions reward *proportion*: block policy violations, require explicit authorisation for irreversible or compliance-sensitive actions, and avoid approvals that add delay without reducing risk.
- When asked how to make agent work auditable, prefer artifacts in standard tooling (plans in issues, pull requests, workflow logs, commit history) over ad-hoc notes.
- For failure analysis, decide first whether it is a reasoning error, tool misuse, or a context or environment problem. The right tuning step (instructions, tool access, memory or environment) follows from that.
- English only: if English is not your first language, request the extra 30 minutes when you book.
- Answer every item. Microsoft's [exam scoring page](https://learn.microsoft.com/en-us/credentials/certifications/exam-scoring-reports) says there is no penalty for guessing.
