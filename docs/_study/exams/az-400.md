## Retirement notice: plan around February 1, 2027

Microsoft's Skills Hub [announcement of the Agentic DevOps Engineer Expert certification](https://techcommunity.microsoft.com/blog/skills-hub-blog/new-microsoft-certified-agentic-devops-engineer-expert/4528356) (October 15, 2026) says that with that release, **Exam AZ-400 and the Microsoft Certified: DevOps Engineer Expert certification will retire on February 1, 2027**. As of 2026-10-24 the [exam page](https://learn.microsoft.com/en-us/credentials/certifications/exams/az-400/) still shows "Retirement date: none", so the two official sources disagree. This file uses the date from the announcement. The successor is **AZ-401** (*Designing and Implementing Microsoft Agentic DevOps Solutions*), which keeps almost all of AZ-400's skills and adds AI-assisted and agentic tooling.

What this means for you. AZ-400 is stage 6 in this roadmap, and February 2027 is only a few months away. Unless you are ready to sit AZ-400 now, prepare for AZ-401. Everything below still describes AZ-400 accurately, and most of it carries over to AZ-401 bullet for bullet.

## What the exam really tests

The build and release pipelines domain carries half the exam (50–55%), so AZ-400 is above all a pipelines exam. It expects you to cover both **GitHub** (Actions, Advanced Security, Packages, Projects) and **Azure DevOps** (Pipelines, Boards, Repos, Artifacts) evenly.

- **Processes and communications (10–15%).** GitHub Flow, feedback through notifications and Issues, traceability between work items and commits, the DORA-style flow metrics (cycle time, lead time, time to recovery) on dashboards and queries for every phase, wikis with Markdown and Mermaid, release notes generated from Git history, webhooks, and the Boards-to-GitHub and Teams integrations.
- **Source control (10–15%).** Trunk-based, feature and release branching, branch policies versus branch protection rules, Git LFS and git-fat, Scalar for large repositories, repository permissions and tags, and recovering or purging data (for example removing a committed secret from history).
- **Build and release (50–55%).** Package feeds, views and upstream sources in Azure Artifacts and GitHub Packages, with SemVer and CalVer. Testing strategy, quality and release gates, and code coverage. YAML pipelines, triggers, multi-stage and parallel jobs, templates, variable groups and environments with checks and approvals. Agent and runner infrastructure (Microsoft-hosted versus self-hosted, cost and licences). Deployment patterns (blue-green, canary, ring, feature flags with Azure App Configuration, slot swap) and database deployments. IaC with Bicep and ARM, Azure Automation State Configuration, Azure Machine Configuration and Azure Deployment Environments. Pipeline health, flaky tests, retention, and migrating classic pipelines to YAML.
- **Security and compliance (10–15%).** Service principals versus managed identities, GitHub Apps versus GITHUB_TOKEN versus PATs, Azure DevOps service connections, permissions and access levels (stakeholder access, outside collaborators), Key Vault, workload identity federation with OpenID Connect, secure files, preventing secret leakage, GitHub Advanced Security on both platforms, Defender for Cloud DevOps security, CodeQL in containers, and Dependabot.
- **Instrumentation (5–10%).** Azure Monitor and Application Insights, VM, Container and network insights, GitHub insights and charts, alerts on pipeline events, distributed tracing, and basic KQL.

Where candidates lose points: equivalent features with different names on the two platforms (branch policies vs branch protection rules, environments with checks vs environment protection rules, variable groups vs secrets and variables), YAML details such as `dependsOn` and `condition` expressions and template parameters, choosing the right deployment pattern for a stated risk, and which identity to use for a pipeline that deploys to Azure (workload identity federation, not a stored secret).

## Study strategy

1. **Get the prerequisite.** You need AZ-104 for the credential.
2. **Foundations first: Git and YAML.** Practise branching, rebasing, LFS and history rewriting until they are routine.
3. **Build the same pipeline twice.** Take a small .NET API with an Angular front end (your own stack). Build, test with coverage, publish a package, and deploy to App Service with slots, once with GitHub Actions and once with Azure Pipelines. Use OIDC federation on both, a Key Vault-backed variable group or secret, an environment approval, and a canary or slot swap.
4. **Add security scanning.** Turn on GitHub Advanced Security (code scanning with CodeQL, secret scanning, Dependabot) and look at the same results in Defender for Cloud DevOps security.
5. **Instrument.** Add Application Insights, write a few KQL queries, and set an alert that fires on a failed deployment.

Official resources: the [AZ-400T00 course](https://learn.microsoft.com/en-us/training/courses/az-400t00) and its self-paced paths, the free practice assessment linked from the exam page, the Exam Readiness Zone videos, and the study guide's documentation list (DevOps resource centre, Azure DevOps documentation, Azure Boards, Key Vault, Azure Monitor, Azure Pipelines, Azure Repos, *Work with Azure DevOps and GitHub*).

How your background helps or misleads:

- **AZ-204 preparation** helps with App Service slots, App Configuration feature flags, Key Vault, managed identities and Application Insights. All of them appear here from the delivery side.
- **CKAD preparation** helps with container deployment and rolling or canary ideas. Kubernetes manifests aren't tested directly, though.
- **.NET background** makes the build, test and coverage tasks familiar. Practise the YAML rather than relying on the classic editor, which is now only a migration topic.
- **AWS knowledge.** CodePipeline, CodeBuild and CodeDeploy map loosely to Azure Pipelines. The exam is mostly about GitHub and Azure DevOps, though, not about cloud CI services.

## Differences from related exams

- **AZ-400 vs DOP-C02 (AWS Certified DevOps Engineer – Professional).** DOP-C02 is about running workloads: SDLC automation with AWS Code services, configuration management and IaC (CloudFormation, CDK), resilient cloud solutions, monitoring and logging, incident and event response, and security and compliance. AZ-400 cares much more about process (work tracking, branching, Git hygiene, metrics) and about two tool platforms (GitHub and Azure DevOps), and much less about operating the runtime or responding to incidents.
- **AZ-400 vs AZ-401.** AZ-401 keeps the same five domains but cuts the pipeline weight to 35–40% and raises instrumentation to 15–20%. It adds MCP servers (Azure DevOps and GitHub), GitHub Copilot in pipelines, tests and branch rules, GitHub Agentic Workflows, Git worktrees and hooks, Azure DevOps-to-GitHub migration, and AI agents for operations (Azure Copilot Observability Agent, Azure SRE Agent). It drops Scalar, git-fat, Azure Deployment Environments, Azure Automation State Configuration and Azure Machine Configuration, and classic-to-YAML migration.
- **AZ-400 vs GH-200 (GitHub Actions) and GH-500 (GitHub Advanced Security).** Those go deeper on one GitHub product each. AZ-400 covers them at the level needed to design a whole delivery system.
- **AZ-400 vs AZ-104 and AZ-204.** These are the associate prerequisites. AZ-400 assumes you can already run or build on Azure, and tests how you deliver changes to it.

## Exam-day notes

- Half the score is pipelines, so if time is short, give pipeline questions the most care.
- Read YAML snippets line by line: indentation, `dependsOn`, `condition`, trigger paths and template parameter types are where the traps are.
- When both GitHub and Azure DevOps options appear, check which platform the scenario uses before choosing.
- For "most secure" deployment identities, prefer workload identity federation or managed identity over PATs and stored secrets.
