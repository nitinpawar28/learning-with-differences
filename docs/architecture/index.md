# Architecture

An architect makes decisions that are expensive to reverse, and has to defend
them with evidence: quality attributes, trade-offs, risks and cost. This area
teaches that practice and the building blocks it uses, compared option by
option.

## What this area covers

| Domain | Focus |
|---|---|
| Architecture practice | The architect role, quality attributes and scenarios, trade-off analysis, architecture decision records (ADRs), the C4 model, arc42, fitness functions, governance |
| Well-Architected | The Azure and AWS Well-Architected frameworks: pillars, design principles, reviews and lenses, and how they differ |
| Cloud adoption and migration | The Microsoft and AWS Cloud Adoption Frameworks, migration strategies (the 7 Rs), portfolio assessment and wave planning |
| Cost and FinOps | FinOps principles, allocation, unit economics, forecasting and commitment discounts |
| Enterprise architecture | The TOGAF Standard and ADM, capability maps, EA frameworks compared |
| Patterns and styles | Architecture styles, cloud design patterns, integration patterns, domain-driven design |
| Distributed systems | CAP and PACELC, consistency models, consensus, replication, partitioning, ordering and idempotency |
| Data architecture | OLTP vs. OLAP, warehouse vs. lake vs. lakehouse, medallion, data mesh, CDC, polyglot persistence |
| Reliability | HA vs. DR vs. fault tolerance, SLA/SLO/SLI and error budgets, RTO and RPO, multi-AZ and multi-region design |

## Exams this area prepares for

AZ-305 (Azure Solutions Architect Expert), SAP-C03 (AWS Solutions Architect –
Professional), SC-100 (Cybersecurity Architect Expert), the TOGAF Enterprise
Architecture certifications and iSAQB CPSA-F. The details are on each exam's
page under [Exams](../study/exams.md).
