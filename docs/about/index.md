# How this library works

## The method: learning by differences

Experts are defined less by how much they know than by how precisely they can
tell similar things apart: OAuth from OpenID Connect, an Azure Policy from an
AWS service control policy, an agent from a workflow, a prompt injection from a
jailbreak. Educational research calls this *variation*: you learn what
something is by seeing it next to what it is not. Every page here is built on
that idea.

- **Every glossary term** has a *How it differs* section that names its
  near-neighbours and states the one difference that matters for each.
- **Every Azure or AWS term** lists its counterpart on the other cloud with a
  [fidelity rating](../glossary/legend.md#fidelity) (exact, close, partial or
  none), and says why the match is not one-to-one.
- **Comparison articles** set two options against each other along the
  dimensions that change a design decision.

Study each topic in three steps: **read** the article and its terms, **do**
the lab, then **prove** it with the self-check questions and, where there is
one, a design kata or threat model.

## How the library is organised

| Area | What it covers |
|---|---|
| [Architecture](../architecture/index.md) | Architecture practice, Well-Architected, migration, cost, enterprise architecture, patterns, distributed systems, data architecture, reliability |
| [Cloud](../cloud/index.md) | Cloud foundations; Azure and AWS across 12 matched capabilities; Azure-vs-AWS comparisons |
| [AI](../ai/index.md) | AI foundations, applied generative AI, evaluation and operations, agents, agent protocols, AI platforms |
| [Security](../security/index.md) | Foundations, identity, threat modeling, AppSec, supply chain, cryptography, cloud security, detection and response, network security, data protection, GRC, AI security |

| [Practice](../practice/index.md) | Labs, design katas, threat models, incident tabletops, capstones |

Pages live at `<area>/<domain>[/<group>]/<page>.md`. For example,
`cloud/azure/identity/` holds Azure identity pages, and
`cloud/compare/identity/` holds the comparison with AWS identity.

## Reading a page

- **Linked tabs.** Wherever a page shows Azure and AWS side by side, or C# and
  Python, choosing a tab switches every matching tab group on the page. The
  choice stays as you navigate.
- **Acronym tooltips.** Hover over an underlined acronym on any page to see its
  expansion and a one-line definition. Ambiguous acronyms, such as WAF, list
  every meaning.
- **Levels.** *Foundation* means fundamentals-exam depth, *practitioner* means
  associate or specialty depth, and *expert* means professional or expert
  design depth.
- **Status.** Pages are *stubs* (scope only), *drafts* (written, not fully
  verified) or *complete* (verified against primary sources, with a
  verification date). The navigation shows a badge for stubs and drafts.
- **Freshness.** Cloud and AI move fast. Every verified page records when it
  was last checked. AI content is re-verified every 90 days, cloud services
  every 180 days and fundamentals every two years; overdue pages carry a
  warning. The [freshness report](../study/reports/freshness.md) lists them all.

## Studying for an exam

1. Open the exam's page from [Exams](../study/exams.md). It lists the official
   objectives, the pages that cover each one, and the gaps that remain.
2. Work through the matching [learning path](../study/paths.md), doing the labs
   as you reach them.
3. Drill the vocabulary with the exam's Anki deck (linked from the exam page),
   and answer the self-check questions at the end of each article and term.
4. When you pass, set `progress: passed` and `passed_on` in the exam file, and
   the [renewals page](../study/renewals.md) will track the expiry date.

## How the library is built

The site is generated by [Zensical](https://zensical.org/). Glossary terms,
exams and learning paths are written as source files under `docs/_terms/`,
`docs/_study/` and `docs/_data/`. A small generator, `lwd`, compiles them into
pages, indexes, the Explorer data, tooltips, coverage tables and flashcards.
See [Engine notes](engine.md) for the commands and the validation rules.
